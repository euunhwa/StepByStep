# EasyCar0.7.0 · 세 메뉴와 분할 화면 검증

확인일 2026-11-06 / Asia·Seoul. 실제 프로젝트 `/Users/genius/AndroidStudioProjects/EasyCar`에서 빌드하고 Pleos Connect v2.1.0에 설치했다. CPU2코어/RAM3GB 에뮬레이터 한 대만 사용했고 Gradle과 동시에 실행하지 않았다.

## 변경

- 메뉴를 **홈·기록·설정**으로 줄이고 성장 메뉴/화면을 제거했다. 기록 목록과 조회 동작의 명칭도 기록으로 통일했다. 기존 주행 기록은 삭제하지 않았다.
- 가용 폭900dp 미만 또는 높이500dp 미만이면 간결한 화면을 사용한다. 정차/시작 전에는 세 메뉴와 연결 상태·코칭 시작만 제공하며, 낮은 높이는 긴 소개/카드까지 생략한다.
- 코칭 중에는 메뉴·원시 신호·최근 기록을 숨기고 출처·상태·최대3줄 코칭·임시 점수/보류·큰 종료 버튼을 표시한다. 데모가 일시정지된 때만 계속 버튼을 추가한다.
- 5초 카드 만료·다음 동작 대기·기록 보존은 유지한다. 인식 r1, 평가 참조셋/프로필0.2와 정책0.3의 값/배점은 바꾸지 않았다.
- 사용자 제안 API/평가 자료는 [별도 검토](evaluation-candidates-2026-11-06.md)에 기록했다. DLP/Geotab을 실제 확보한 전문가 정답셋이나 현재 배점 출처로 바꾸지 않았다.

## 화면 확인 범위

이번 계측은 실제 Pleos 기기에서 EasyCarApp에 해당 제약 크기를 주어 **실제 화면 분기와 서비스 상태**를 확인했다. 목업 데이터로 UI만 그린 결과가 아니다. 다만 OS 창의 실제 손잡이를 움직인 시험과는 구분한다.

현재 컴퓨터 제어에서 독립 Pleos 에뮬레이터 창은 선택되지 않았고 Android Studio Running Devices에도 연결 기기가 나타나지 않아, 이번 버전의 시스템 손잡이 드래그는 재검증하지 못했다. 다른 AVD를 추가로 실행하지 않았다. 실제 Pleos 분할 손잡이/내비 동시 표시의 이전 검증은 [v0.4 기록](verification-v4-ko.md)에 있다. Pleos 기본 넓은 창도 multi-window로 보고하므로 해당 플래그 대신 실제 가용 크기를 사용한다.

최초 캡처 한 장이 크기 변경 직전 렌더 프레임을 담는 것을 발견해, 테스트에서 idle/미니 화면을 확인한 뒤 캡처하도록 보완했다. 제품 코드가 아닌 검증 APK만 다시 빌드하고 해당 흐름을 재확인했다(10.838초, OK 1 test). 최종 스크린샷은 제약 크기를 부여한 계측 화면이며 실제 OS 손잡이 드래그 사진으로 표시하지 않는다.
