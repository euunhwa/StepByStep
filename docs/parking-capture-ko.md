# 주차 녹화·최종 배치 실험 기록(현재 앱에서 제외)

> 최신 화면은 [현재 UI 캡처](ui-screenshots-ko.md), 최신 시연은 [영상 안내](../media/README.md)에서 확인할 수 있습니다. 아래 화면·로그는 현재 앱에서 제외한 0.13.0 실험의 검증 근거로 보존합니다.

현재0.13.1은 사용자 요청으로 이 기능을 앱에서 제외했다. 상위 메뉴는 홈·기록·설정만 제공한다. 아래는0.13.0 당시 구현·검증 기록이며 현재 사용법이 아니다. 실험 원본은 [보관 폴더](../experimental/parking-capture-v013/README.md)에 있다. 실제 탑뷰 제공 조건은 [현재 README](../README.md)에 유지한다.

2026-11-07 · 보관 실험 앱0.13.0(code16) · `parking-outcome-draft-1.0`

## 구현한 흐름

1. 정차 후 **주차** 메뉴에서 영상의 기기 내 저장에 동의한다.
2. **주차 화면 선택 · 녹화 시작**을 누르고 Android 화면 공유를 승인한다. 매번 새 승인이 필요하다. 전체 화면 또는 시스템에서 제공하는 녹화 대상을 선택하며, 어라운드뷰를 별도 앱에서 표시한다면 그 화면이 실제 녹화 대상에 포함되어야 한다.
3. 차량 신호를 수집하며 안정된 R→D 횟수를 표시한다. 다른 앱을 열어도 녹화 서비스와 신호 수집을 유지한다. 시작 당시 P단이라는 이유로 즉시 종료하지 않는다.
4. 주차 조작을 마치고 약1초 이상 정차한 뒤 P단을1초 유지한다. 이동을 관측한 경우 자동 종료하고 전체 MP4와 횟수·완료 근거를 같은 기록에 저장한다. 직접 종료·시스템 공유 중단은 중단 사유를 남긴다.
5. 결과에서 최종 장면을 확인한다. **차량 축이 위아래 방향인 왜곡 보정 탑뷰**에서 실제 차체의 왼쪽 위·오른쪽 아래를 누른다. 주차선 네 경계 자동 검출을 실행하거나, 선 안쪽의 네 모서리를 둘레 순서대로 추가 지정한다. 보정·실제 외곽 확인 후 분석하면 전후진과 최종 배치를 합친 임시 점수를 공개한다.
6. 결과에 각 감점 원인과 측정값을 표시하고 **저장한 전체 주차 영상 보기**로 재생한다. Room 재시작과 저장 기록 조회/Gleo 설명에도 같은 점수와 버전을 사용한다. 이미 공개한 점수는 재분석으로 덮어쓰지 않는다.

실제 화면은 자동으로 차체 외곽을 검출하거나 카메라 왜곡을 보정하지 않는다. 어라운드뷰의 차량 아이콘이 실제 차체보다 작거나 여백을 포함한다면 그 아이콘을 그대로 실제 외곽으로 지정하면 안 된다. 원근 후방 영상은 이 채점 방식의 입력이 아니다.

## 입력과 녹화

- `ScreenParkingRecorder`: Android MediaProjection + foreground mediaProjection service + MediaRecorder. 오디오를 수집하지 않는다. EVS 비공개 장치나 서명 권한을 사용하지 않는다.
- H.264 MP4,15fps,목표3Mbps,긴 변 최대1280px,최대5분·250MB. 시작 시100MB 이상의 저장 공간을 요구한다. 시스템/인코더 오류나 한도 도달 시 중단하고 실제 파일을 검사한다.
- `.pending.mp4`로 기록한 뒤 정상 종료·길이300ms 이상·파일1KB 이상·메타데이터 확인을 통과한 파일만 최종 MP4로 바꾼다. 실패를 `videoSaved=true`로 기록하지 않는다.
- `USER_SELECTED_SCREEN`은 **사용자가 선택한 실제 화면 녹화**이며 AVM 센서 직접 입력이 아니다. `SYNTHETIC_REPLAY`는 번들 합성 MP4·신호를 재생한 별도 출처다. 영상과 기록은 기기에 저장하고 삭제/보관 기간 정리를 적용한다.
- 녹화 시작의 `elapsedRealtime`을 영상0ms와 연결하는 **근사 시간 매핑**이다. 센서·카메라 PTS의 하드웨어 동기화가 아니다. 메타데이터에 `ELAPSED_REALTIME_APPROXIMATE_NOT_CAMERA_PTS`를 남긴다. 프레임 분석도 MediaMetadataRetriever의 요청 시점 기반이므로 정확한 원본 PTS 보장은 없다.
- P단이 되면 카메라 화면이 닫힐 수 있어 P 진입150ms 전을 최종 요청 시점으로 잡고, 그 앞600ms의5개 요청 프레임을 검사한다. P 진입 전500ms 이상의 정차가 없거나 시점이 실제 영상 길이를 벗어나면 점수를 보류한다. 실차 지연·화면 전환과 시계 오차 검증은 별도다.

## 횟수와 최종 배치

`ParkingEpisodeTracker`는 명시적 시작부터 속도·기어를 관측한다. D/R 이동속력>0.15m/s를 한 번 이상 관측해야 하고, 이후 속도≤0.15m/s+P를1000ms 유지해야 자동 완료한다. 기어500ms 안정, 신호 신선도750ms,1초 초과 수신 공백 거부, 시작500ms 초과 첫 신호 도착 거부, 최소10유효 프레임을 적용한다. N 경유 R→D는 포함하며 P/신호 누락은 전환 연결을 끊는다. 전체 횟수 관측이 끊기면 점수는 보류한다. 이 경로는 yaw나 T/평행 유형을 필수로 요구하지 않는다.

`ParkingSlotAnalyzer`는 기존 측면선 검출에 앞뒤 경계 검출을 더한다. 선 중심 대신 선 두께 안쪽의 네 경계를 사용한다. `ParkingPlacementGeometry`는 보정 직사각형의 긴 축을 비교하고 다음을 계산한다.

- 차량/주차칸 긴 축의 차이0~90°.
- 두 중심 간 좌우 투영거리 / 주차칸 전체 폭, 앞뒤 투영거리 / 주차칸 전체 길이.
- 네 경계 각각에 대한 차체 네 모서리의 최소 부호 거리. 모든 경계에서2px 초과 여유면 안쪽, 하나라도−2px 미만이면 침범, ±2px면 불확실.

측면 검출은 기존 Hough/회귀 수치를 사용하되 유효 지지 행 비율만0.42→0.25로 적용한다. 앞뒤 경계는 두 측면의 중간 축에 수직으로 검색한다. 반폭의88% 내부를2px 간격으로 읽고, 유효 표본 수≥반폭×0.35·대비 지지60% 이상이면 후보로 삼는다. 후보 간격≤5px를 묶고 축 중앙에서8px 이상 떨어진 가까운 앞/뒤 묶음을 선택한다. 흰색 RGB차≤55 또는 노란색(min(R,G)−B≥25,G≥0.65R,R≥0.75G), 휘도≥70·축 방향±5px 대비≥20을 사용한다. 관측한 선 두께 반폭을 안쪽으로 이동하며 측면 보정은0~12px로 제한한다. 이 수치는 실측 조정 전 영상 휴리스틱이다.

최소 변10px·볼록·직각 오차 내적인자<0.15인 사각형만 받는다. 실제 픽셀 검사에서는 최소3개 요청 프레임·400ms 이상 구간, 동일 해상도, 지정 경계 중3개 이상에 흰색/노란색 선 근거를 요구한다. 각 경계의 유효 표본8개 이상·지지율35% 이상, ±5px 검색, 밝기>70·법선9px 비교 대비>20을 적용한다. 최종 장면과 영역 평균 밝기 차이가10을 넘으면 화면/위치 변화로 보류한다. 수동 지정도 이 픽셀 검사를 생략하지 않는다. 이는 제한된 초기 영상 휴리스틱이며 장애물·충돌·휠스톱·실제 안전을 판정하지 않는다.

평가 수치와 식은 [평가 문서](datasets/evaluation-ko.md), 실행 원본은 [정책 JSON](../experimental/parking-capture-v013/app/src/main/assets/profiles/parking-outcome-v1.json)과 [채점기](../experimental/parking-capture-v013/core/src/main/kotlin/com/easycar/core/ParkingOutcome.kt)다. 기존 T자/평행 동작 점수와 별도 버전이며 과거 점수는 유지한다.

## 예제와 검증의 의미

주차 메뉴의 정렬·선 침범·선 없음 예제는 `tools/generate_parking_capture_video.swift`로 생성한480×360·15fps·약6.53초 MP4와 합성 기어/속도다. 정렬 예제는 R→D2회→추가1회5점 감점→95점, 침범은59점 이하, 선 없음은 보류를 기대하는 회귀 사례다. 실제 카메라/주차 데이터셋이나 전문가 정답이 아니다. 코드에 점수를 넣지 않고 기기 MP4 디코딩·경계 검출·집계·채점·저장을 실행한다. 자산 출처/해시는 [합성 자산 명세](validation/parking-capture-fixtures-v013.json)에 둔다.

실제 MediaProjection 승인→MP4 저장→디코딩도 별도 장치 검사한다. **실제 화면 녹화 성공은 어라운드뷰 직접 입력·보정·최종 배치 정확도 검증과 구분한다.** 현재 에뮬레이터의 일반 카메라 화면은 도로를 보는 원근 영상으로 확인됐으며 주차칸이 보이는 보정 탑뷰를 제공하지 않는다. EVS 직접 접근에는 현재 앱에 없는 서명/privileged 권한이 필요하다. 보호된 화면·차종별 실제 AVM·인식률/오탐률·전문가 배점은 별도 검증이 필요하다.

일반 런처 카메라 버튼으로 화면을 전환한 뒤에도 MP4에 도로 카메라 화면이 담기는 것을 [실제 녹화에서 추출한 프레임](validation/parking-camera-probe-frame-v013.png)으로 확인했다. 이 기기에서 관찰한 화면 캡처 결과이며 다른 OEM 화면의 녹화 허용을 보장하지 않는다.

검사 결과와 최초 실패/재시험은 [0.13 검증 기록](validation/parking-capture-summary-v013.json)에 기록한다.

Android 구현 근거: [MediaProjection](https://developer.android.com/media/grow/media-projection), [보호 화면 FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE), [AAOS EVS](https://source.android.com/docs/automotive/camera/evs/camera-hal).
