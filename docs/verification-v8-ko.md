# EasyCar0.8.0 · 점수·짧은 원인·색상 검증

확인일 2026-11-06 / Asia·Seoul. 지정 프로젝트에서 최종 APK를 빌드하고 Pleos Connect v2.1.0 한 대에 설치했다. CPU2코어/RAM3GB로 제한했고 Gradle과 에뮬레이터를 동시에 실행하지 않았다.

## UI 변경

- 차량 일곱 동작 자동 코칭 배지, 중복 관측 중 제목, 대기 설명 문구를 실시간 화면에서 제거했다. 대기에는 다음 동작 대기 중만 표시한다.
- 긴 관측 최고 속도/보류 설명 대신 **N점 + (원인 : 급감속)** 같은 짧은 측정 항목을 표시한다. 상세 코칭·측정값·기준은 기록에 보존한다.
- 100점 초록(#9AE7C4),80~99점 주황(#FFB454),0~79점 빨강(#FF6B6B)을 전체·낮은 높이·분할·기록 점수에 적용했다. 미평가/null은 중립색 평가 대기이며0점이나100점으로 바꾸지 않는다.
- 분할에도 같은 짧은 원인을 표시하고5초 뒤 대기로 복귀한다. 데모 표기와 임의 평가셋/개선 필요 공지는 유지한다.

## 평가 의미 변경

사용자 요청으로 현재 임의 관측 모드에 score_unconfirmed_braking_observations=true와 OBSERVED_CONTROL_SMOOTHNESS_NOT_FAULT를 명시했다. 제동 상황 원인이 미확인이어도 측정 강도·지속시간에서 조작 부드러움 점수를 계산한다. 이 상황의 과실/위험 회피 적절성은 판정하지 않으며 주석을 결과에 저장한다. 기존/전문가 정책의 원인 보류는 유지하고 필수 신호/시간/공간 부족 보류도 유지한다.

비교값/7종926표본/인식 r1은 그대로다. 프로필0.3·정책0.4로 올렸고 참조셋 ID0.2를 유지했다. 이전 기록을 새 기준으로 몰래 다시 채점하지 않는다. [평가용 관리 문서](datasets/evaluation-ko.md)와 [변경 이력](datasets/CHANGELOG-ko.md)에 이전 정책과의 차이를 기록했다.

차량 입력 재생은 **과거 localhost에서 실제 콜백으로 수집한 기록의 재계산 시험**이며 이번에 실차를 주행하거나 신규 콘솔 조작을 한 시험은 아니다. 해당0점은 당시 콘솔의 강한 제동 노출로 산출된 임의 관측 점수이며 운전자 과실 판단이 아니다.

색상 경계 검증에는 명시적인 UI 시험 점수를 사용했다. 캡처의90점은 합성 측정값을 실제 채점 엔진으로 계산한 예제다. 가짜 주행 기록으로 저장하지 않았다. 만료 시험은 별도 제출 데모를 명시적으로 시작하고 무음으로 수행했다.

UI 기기 시험은 실제 앱 컴포넌트에 제약 크기를 부여해 검증한 것이며 이번 버전에서 시스템 분할 손잡이를 직접 드래그한 사진으로 표시하지 않는다. 실제 시스템 분할의 이전 범위는 [v0.7 검증](verification-v7-ko.md)과 연결된 기록을 따른다.
