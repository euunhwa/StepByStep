# 주차 영상 분석 개선 · 0.10.0

> 최신 화면은 [현재 UI 캡처](ui-screenshots-ko.md), 최신 시연은 [영상 안내](../media/README.md)에서 확인할 수 있습니다. 아래 화면·로그는 0.10.0 당시의 검증 근거로 보존합니다.

2026-11-07 · versionCode 13 · 영상 분석 `parking-vision-2.0`.

## 사용 방법

1. 정차 상태에서 시작 안내에 동의하고 **기록 → 영상 분석 예제 보기**를 엽니다.
2. 정렬·기울어짐·선 침범·가림·선 없음 중 하나를 선택합니다. 예제는 기존 번들 합성 탑뷰 MP4이며 차량 카메라 녹화가 아닙니다.
3. 현재 프레임에서 검출한 주차선, 제공된 차량 영역, 상대 각도, 좌우 최소 여유를 확인합니다.
4. 영상을 멈춘 뒤 **이 위치 앞 1초 분석 · 저장**을 누릅니다. 직전 구간의 최대 5개 요청 시점에서 관측이 일관된지 검사하고 결과를 기록에 보존합니다.
5. 사용자 영상은 **영상 가져오기**로 추가하고, **탑뷰 보정 정보 연결**에서 본인 영상의 보정 JSON을 연결합니다. 보정 예제의 차량 좌표를 실제 영상에 복사하지 않습니다.
6. 여러 주차칸이 있으면 일시 정지 후 검출된 두 선 사이를 누릅니다. 선택 해제로 모호한 상태를 다시 확인할 수 있습니다. 보정 연결·대상 칸 선택과 해제는 현재 재생 위치의 구간에 적용됩니다.

현재 프레임과 저장한 구간은 별도 표시합니다. 재생 위치를 바꾸어도 이전에 저장한 결과의 분석 시각을 표시하며 새 구간을 자동으로 저장하지 않습니다. 영상만 있는 예제에는 동작 점수와 차량 신호를 만들지 않습니다.

## 변경 내용과 수치

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| 선 픽셀 후보 | RGB 최솟값 >195, 색차 <45인 밝은 흰색 | 휘도 ≥48, 수평 이웃 평균 대비 ≥22인 흰색·노란색 후보 |
| 흰색 / 노란색 조건 | 흰색만 | 흰색 RGB 최대−최소 ≤55. 노란색 min(R,G)−B ≥25, G≥0.65R, R≥0.75G |
| 이웃 거리 | 미사용 | `max(6, width/80)`px. 균일한 밝은 바닥을 선으로 채택하지 않음 |
| 선 탐색 | 수직 기준 ±25°, 0.5° 간격 | 같은 탐색 각도. 투표 후보 문턱 h/3 → 0.20h, 실제 선 지지 검사로 후속 거부 |
| 실제 지지 검사 | 전체 행의 45% | 전체 분석 행의 42% 이상, 관측 가능한 행의 55% 이상, 수직 지지 범위 65% 이상. 차량 위·아래까지 관측 필요 |
| 대상 칸 위치 | 화면 중앙 기준 | 제공된 차량 외곽의 중앙 기준. 비스듬한 선은 실제 누른 행에서 인접 선을 찾음 |
| 선 폭과 여유 | 선 중심까지 수평 거리 | 관측 선 두께의 안쪽 경계부터 차량 앞·뒤 모서리까지 최소 수직 거리 |
| 침범 경계 | 거리 <0이면 침범 | −2px 미만이면 침범, 양쪽 >2px이면 미관측. 그 사이에는 침범 여부 보류 |
| 거리 | 선택적 m 표시 | 보정 스케일이 없으면 px만 표시. 스케일이 있을 때만 m와 중앙 편향 환산 |
| 저장 결과 | 한 프레임 | 직전 최대 1초의 5개 요청 시점 비교. 마지막 요청 시점의 관측 필수 |
| 보정 변경 | 조건에 따라 동작 결과 재계산 | 영상 근거만 갱신. 기존 동작 점수·평가 근거·피드백·음성·차량 프레임 유지 |

추가 유지 조건: 두 선 방향 차이 ≤3°, 후보 간 중앙 절편 간격 ≥0.12w, 차량 앞·뒤에서 두 선 사이 폭 ≥0.18w. 픽셀 수집은 2px 간격이며 선 지지는 모든 행을 검사합니다. 최소제곱 회귀는 후보 주변 ±8px를 사용합니다. 거리의 선 두께는 관측 행에서 측정한 밝은 선 연속 폭의 중앙값으로 추정합니다. 값은 시제품의 공학 설정이며 실차로 보정된 기준이 아닙니다.

좌우 여유는 각 선에 수직인 거리입니다. 중앙 편향은 차량 중앙−주차칸 중앙의 수직 거리이며 양수는 오른쪽입니다. 음수 여유는 제공된 차량 영역과 주차선 안쪽 경계가 겹친다는 의미이며 실제 연석 접촉이나 차체 손상을 판정하지 않습니다. 직선인 두 측면 선만 다루므로 앞뒤 경계와 장애물, 주차 성공 전체를 판단하지 않습니다.

## 여러 프레임을 비교하는 조건

- 시점: 선택 위치부터 최대 1초 전까지 균등한 5개 요청 시점. 최소 관측 시간 400ms, 최대 1500ms.
- 동일 출처, 서로 다른 요청 시각, 유효한 최근 관측이 필요합니다. 최소 3개이면서 요청 수의 60% 이상인 유효 관측을 요구합니다.
- 마지막 요청 시점에서 선이 없거나 보류되면 이전의 좋은 장면을 대신 쓰지 않습니다.
- 관측 간 침범 상태가 같고, 상대 각도 범위 ≤2°, 중앙 편향과 좌·우 여유 범위가 각각 ≤8px이어야 합니다.
- 조건을 통과하면 최신 프레임의 기하 관측을 보존하고, 지지율은 유효 관측의 최솟값을 저장합니다. 성공 확률이나 평균 정렬 점수가 아닙니다.
- 영상 디코더의 가까운 실제 프레임을 사용합니다. 저장 시각은 **요청한 영상 시각**이며 디코딩된 프레임의 정확한 PTS나 차량 센서 측정 시각을 보장하지 않습니다. 중복된 이미지도 정차 영상에서는 정상일 수 있습니다.
- 영상 변화에 대한 보류이며 실제 차량 정차·속도 추정이 아닙니다. 차량 신호의 시간 매핑은 별도 계약을 사용합니다.

각도 ≥3° 또는 중앙 편향 절댓값 >4px일 때의 복기 문구는 영상 표시용 안내입니다. 이 값으로 감점하거나 안전성을 분류하지 않습니다.

## 호환성과 자원 처리

`AlignmentEvidence`에 알고리즘 버전, px 여유, 중앙 편향, 요청/유효 프레임 수와 구간 시작 시각을 선택 필드로 추가했습니다. 과거 JSON은 새 필드 없이 읽을 수 있습니다. 과거 영상 근거는 자동 재분석하지 않으며 사용자의 새 분석 동작에서만 갱신합니다. 기존 프로필·인식/평가 JSON·점수 버전은 그대로입니다.

분석은 백그라운드에서 긴 변 최대 640px로 축소한 프레임을 한 장씩 처리합니다. 재생 위치 변경 시 오래된 관측을 지우고, 디코딩 실패 시 이전 성공 결과를 남기지 않습니다. 재생·분석은 주행 제한 시 중단하고 영상 화면을 숨깁니다. 표시 중인 비트맵을 조기에 recycle하지 않으며 디코딩에 사용한 일시 비트맵과 retriever를 해제합니다.

## 검증 범위

새 코어 검사 17개와 기존 114개, 앱 JVM 검사 5개를 확인합니다. 어두운 흰색·노란색·붉은 색 거부·균일한 빛 반사·점선·짧은 선·화면 밖으로 치우친 차량·침범 경계·스케일 누락·잘못된 보정·실제 누른 행의 대상 선택·구간 안정성·최근 가림을 포함합니다.

장치 검사는 실제 H.264 MP4 디코딩, 구간 분석, 보정 변경 후 기존 결과 보존, Room 재시작/과거 JSON 호환, 넓은/좁은 창 배치와 주행 제한, 실제 기록 화면의 예제 선택→분석→저장 흐름을 확인합니다. 최종 실행 결과는 다음과 같습니다.

최종 재검사 전 한 차례는 영상·저장 단언 이후 ActivityScenario 종료가 PAUSED에서 대기하다 실패했습니다. [당시 로그](validation/device-parking-video-v010-attempt1.log)를 보존했습니다. ViewModel/저장 검사는 별도 ViewModelStore와 실제 차량 브리지를 사용하도록 수명주기를 분리하고, 실제 Activity의 UI 흐름은 별도 Gallery 검사로 유지했습니다. 검사 APK만 다시 빌드한 후 전체 9개를 재실행해 통과했습니다. 앱 기능 검사 실패를 무시하거나 해당 검사를 제외하지 않았습니다.

Gradle과 에뮬레이터는 동시에 실행하지 않았고, 한 대 CPU2/RAM3072MB에서 확인했습니다. 기존 앱 데이터를 지우지 않고 0.10.0/code13을 설치했고, 검사에서 생성한 기록·임시 파일을 정리하며 사용자 설정을 복원했습니다. 종료 후 앱과 8088 포워딩을 복원했습니다.

새 실차·전문가 영상은 확보하지 않았습니다. 검증 자료는 합성 픽셀과 기존 번들 합성 MP4입니다. 자연광·비·그림자·낡은 선·스티칭·렌즈 왜곡·실측 보정 오차에 대한 성능이나 실제 주차 성공률을 주장하지 않습니다. 실제 카메라·어라운드뷰 연동과 자동 카메라 캘리브레이션은 미구현입니다.
