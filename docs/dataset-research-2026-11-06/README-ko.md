# EasyCar 데이터셋 조사·평가 기준 설계안

확인일 **2026-11-06 / Asia·Seoul**. 이번 작업은 문서 조사, 작은 공개 파일의 형식 확인, 평가 규칙 설계에 한정했다. **Pleos/일반 Android 에뮬레이터, Gradle 빌드, 머신러닝 학습을 실행하지 않았다.** 앱 코드와 실제 채점 프로필도 변경하지 않았다.

## 판단과 권장 조합

자동 인식 개발은 **INTERACTION(일반 주행 궤적) + DLP(주차 궤적/공간) + nuScenes CAN/소형 comma2k19 예제(차량 신호)** 조합이 적합하다. Honda HDD는 동작 라벨 후보지만 접근 조건 때문에 초기 필수 의존성에서 제외한다. nuPlan은 전문가 주행을 다룬 벤치마크의 평가 지표와 승차감 수치를 참고한다.

아래 자료의 목적과 확보 신호를 검토한 결과, **일곱 동작·한국 대상 차종·실제 R→D·공간 조건·운전 강사 점수를 모두 갖춘 완성 모범 데이터셋은 이번 조사에서 확보하지 못했다.** 공개 자료는 인식 연구와 기준 후보 생성에 사용하고, 실제 코칭 점수는 조건이 맞는 전문가 검증 자료로 보정해야 한다. 공개 데이터의 정상 사례 전체를 안전운전 정답으로 간주하지 않는다.

위 활용 판단은 제작자 설명에 근거한 설계 판단이다. 파일별 목록과 필드·누락·허가 상태는 `dataset-catalog.json`에 분리해 기록했다. 데이터셋의 라이선스를 Python 도구/SDK 코드 라이선스로 대신 판단하지 않는다.

### DLP 이용 조건에서 확인한 차이

[제작자 사이트](https://sites.google.com/berkeley.edu/dlp-dataset)는 비상업 사용과 재배포 제한을 안내한다. 한편 [해당 DOI의 DataCite 메타데이터](https://api.datacite.org/dois/10.5061/dryad.tht76hf5b)는 rightsList에 **CC0-1.0**을 명시한다. 직접 내려받은 소형 메타데이터를 `evidence/dlp-datacite.json`에 보존했다.

따라서 공개 DOI JSON, 별도 요청 원본 영상/주석, GPL-3.0 Python 도구를 구분한다. CC0 표기를 원본 영상 전체의 이용 허가로 확대하지 않는다. 제품 상용 학습/배포 전에 적용 배포본과 조건 범위를 확인한다. 이번에는 공개 JSON의 다운로드 링크를 web 도구에서 읽을 때 403이 발생하여 원자료는 받지 않았다. 차단 우회를 하지 않았다.

### 실제로 읽은 소형 CAN 예제

`sample-data/comma2k19/`의 네 파일은 총 **159,680 bytes**다. 공개 Git tree에 기록된 각 파일의 blob SHA-1과 다운로드 파일을 대조하고 SHA-256도 남겼다. Python 표준 라이브러리만 사용해 NPY 헤더와 float 배열을 읽었다.

- 속도와 핸들 각각 4,974개, 약 59.99초. 시각 역순/중복 0.
- 속도 값 배열은 `(4974,1)`, 나머지는 `(4974,)`. 같은 scalar라고 배열 모양까지 같다고 가정하면 파서가 실패한다.
- 중앙 샘플 간격은 약 11.2ms이지만 일정 주기가 아니다. 실제 dt를 사용해야 한다.
- 속도/핸들의 원자료 단위는 제작자 README에 근거한다. 센서 측정 시각인지 수신/기록 시각인지, 차종별 조향 부호는 별도 검증 대상이다.
- 이 구간의 관측 범위나 분위수를 안전 허용 범위로 사용하지 않았다. 실제 기어·주차 공간·일곱 동작 라벨·전문가 평가는 확인한 파일에 없다.

상세 수치와 해시는 `evidence/comma2k19-sample-inspection.json`에 있다. 기존 파일만 다시 검사하려면 다음을 실행한다. 네트워크 접근은 `--download`를 명시한 경우에만 수행한다.

```sh
python3 tools/inspect_comma_sample.py
```

## 일곱 동작 인식을 위한 데이터 라벨 설계

사용자는 코칭 시작만 누른다. 모델의 입력에는 사전에 고른 동작 유형을 넣지 않는다. 학습용 정답과 실시간 입력을 별도 파일/스키마로 관리한다.

| 동작 | 필요한 정답과 근거 | 반드시 함께 넣을 오인 사례 |
|---|---|---|
| 출발 | 정지→실제 이동, 시작/종료 경계, 속도·기어·측정 시각 | 크리프·정체·속도 잡음·주차 과정의 재출발 |
| 정지 | 감속→정차 유지, 경계, 원인 확인 여부 | 일시 감속·센서 끊김·위험 회피 급제동·주차 과정의 멈춤 |
| 좌회전 | 실제 경로/방향 변화와 교차로 맥락, 진입/회전/탈출 경계 | 왼쪽 곡선·차로 변경·주차 진입·후진 조향 |
| 우회전 | 실제 경로/방향 변화와 교차로 맥락, 단계 경계 | 오른쪽 곡선·차로 변경·주차 진입·후진 조향 |
| 유턴 | 실제 방향 전환과 도로 맥락, 단계 경계 | 원형교차로·헤어핀·회차·여러 차례 전후진 |
| T자 주차 | 본 설계에서는 도로축에 직각인 주차칸을 대상으로 정의. 공간축·차체 자세·전체 접근/이동/정렬 경계 | 주차 이탈·단순 후진·사선 주차·P단 대기 |
| 평행주차 | 도로축과 평행한 대상 공간·차체 자세, 전체 경계 | 길가 정차·주차 이탈·단순 후진·P단 대기 |

T자/평행주차는 단순 R→D 파형으로 구분하지 않는다. 도로축/공간축과 차량 경로를 확인하고, 공간이 없거나 사선·유형이 모호하면 `UNKNOWN_PARKING_TYPE` 또는 저속 조작 미확정으로 남긴다. R 진입은 후보 근거이지 주차 확정 조건이 아니다. 공간 근거가 충분하면 전진 진입 주차도 별도로 다뤄야 한다. P단+정차만으로 성공한 주차라고 판정하지 않는다.

주차 안의 출발·정지·회전은 주차 하위 단계로 묶어 같은 조작에 여러 번 감점·음성 안내를 하지 않는다. 감지용 정답 라벨·주행 종료 후 전체 경로는 실시간 특징에 넣지 않는다. DLP 도구의 signed_speed 구현은 앞/뒤 인스턴스를 함께 사용하므로 온라인 입력에 그대로 복사하면 미래 정보가 유입된다. [제작자 구현](https://github.com/MPC-Berkeley/dlp-dataset/blob/main/dlp/dataset.py)

## 안전 관련 사실과 코칭 점수

| 구분 | 다룰 내용 | 필요한 근거/보류 |
|---|---|---|
| 안전 관련 관측 | 신호/주행 가능 구역/주변 객체와의 잠재 충돌 등 | 승인된 주변 인지·지도·명확한 사건 확인이 있어야 함. 속도/핸들만으로 위반·접촉·과실을 확정하지 않음 |
| 조작 품질 | 출발/정지/회전의 가감속·jerk·조향 복원 | 신호 시간·단위·차종·공간 조건을 확인한 허용 범위로 비교 |
| 주차 수행 효율 | 실제 기어 R→D 조정 횟수 | 실제 기어가 없으면 보류. 후진 속도 부호의 변화로 기어를 만들어내지 않음 |
| 주차 결과 | 상대 정렬각·차체 침범·관측 가능한 여유 | 보정된 차체/주차칸 좌표와 마지막 정차 근거 필요 |

안전 관련 사실과 조작/효율 점수를 따로 표시한다. 위험 관측을 다른 항목의 높은 점수로 상쇄하지 않는다. 사고 위험/운전 적격/운전자 과실을 인증하는 종합 안전 점수로 표현하지 않는다. 위험 회피를 위한 급제동은 감속이 크더라도 원인이 확인되지 않으면 자동 과실 감점을 하지 않는다.

## 수치 기준: 출처 있는 참고값과 실제 적용값을 구분

[nuPlan 공식 지표 설명](https://github.com/motional/nuplan-devkit/blob/master/docs/metrics_description.md)의 comfort 기본값과 실제 설정 파일을 확인했다.

| 측정 항목 | nuPlan 참고값 | 직접 확인한 설정 |
|---|---:|---|
| 종방향 가속도 | −4.05 ~ +2.40m/s² | [가속도 YAML](https://github.com/motional/nuplan-devkit/blob/master/nuplan/planning/script/config/common/simulation_metric/low_level/ego_lon_acceleration_statistics.yaml) |
| 횡가속도 절댓값 | 최대 4.89m/s² | [횡가속도 YAML](https://github.com/motional/nuplan-devkit/blob/master/nuplan/planning/script/config/common/simulation_metric/low_level/ego_lat_acceleration_statistics.yaml) |
| 종방향 jerk 절댓값 | 최대 4.13m/s³ | [종방향 jerk YAML](https://github.com/motional/nuplan-devkit/blob/master/nuplan/planning/script/config/common/simulation_metric/low_level/ego_lon_jerk_statistics.yaml) |
| jerk 벡터 크기 | 최대 8.37m/s³ | [벡터 jerk YAML](https://github.com/motional/nuplan-devkit/blob/master/nuplan/planning/script/config/common/simulation_metric/low_level/ego_jerk_statistics.yaml) |

이는 전문가 궤적을 살펴 정한 플래너 벤치마크의 승차감 참고값이다. **법규상 안전 합격선, 한국 차종별 기준, 주차 권장 속도, EasyCar 확정 감점 기준이 아니다.** 한계를 넘었다는 이유만으로 위험 운전이라고 말하지 않는다. 속도만 미분한 종방향 jerk에 벡터 크기 8.37을 적용하지 않는다.

실차 허용값 `B`, 초과 크기 정규화 값 `S`, 노출시간 기준 `tau`는 `evaluation-policy-draft.json`에서 비워 두고 실제 채점을 껐다. 데이터셋에서 계산하지 않은 값을 계산했다고 적지 않았다. 현재 앱의 1.8m/s²·4m/s³·일반 회전 4m/s 등은 기존 합성 데모 임시값이며, 이번 조사로 검증되거나 실차용으로 승격되지 않는다.

### 허용 범위를 확정하는 절차

1. 적용 차종·차체/핸들 모델·공간 조건·노면/날씨·신호 처리 방법을 묶어 프로필을 만든다. 회전 반경/도로 폭을 모르면 모든 유턴에 단일 적정 속도를 부여하지 않는다.
2. 여러 강사가 적절하다고 독립 판정한 사례에서만 동작 단계별 분포를 추정한다. 정상 라벨이나 무사고 기록을 전문가 수용 판정으로 대체하지 않는다.
3. Q95/Q99 등 분위수는 허용 범위/정규화 후보를 만드는 데만 쓰고, 전문가가 허용/개선/보류와 그 원인을 검토한다. 데이터 분포 자체가 안전 규칙은 아니다.
4. 미분 신호의 계측 잡음·필터 지연·측정 시각 불확실성을 평가한다. 수신 시각만 있는 핸들 값에서 신뢰할 수 있는 센서 조향 속도를 꾸미지 않는다.
5. 전문가 점수와 비교해 `B/S/tau`·가중치를 보정하고, 별도 운전자/세션에서 검증한다. 개인의 이전 점수에 맞춰 기준을 자동 완화하지 않는다.
6. 승인한 표본·평가자·오차·적용 범위·처리기 버전과 함께 프로필을 발행한다. 외부 조건에 적용하지 않고, 과거 평가 버전도 바꾸지 않는다.

## 항목별 계산과 배점 제안

아래 배점은 **새 설계안**이며 현재 앱에 적용하지 않았다. 검증되지 않은 공개 자료나 소형 예제만으로 실차 점수를 활성화하지 않는다.

| 동작 | 평가 그룹 / 감점 상한 합 100점 |
|---|---|
| 출발 | 가속·종방향 jerk를 같은 원인으로 묶어 더 큰 감점 하나: 최대 100 |
| 정지 | 원인이 확인된 감속·종방향 jerk 중 큰 감점 하나: 최대 100. 원인 미확인 급감속은 과실 감점 보류 |
| 좌회전 | 진입/회전/탈출 속도 합 최대 40 + 종방향 부드러움 최대 30 + 조향/복원 최대 30 |
| 우회전 | 위와 같은 그룹, 실제 조건/방향의 전문가 기준은 별도로 검증 |
| 유턴 | 위와 같은 그룹, 유턴 공간/반경 조건에 맞는 기준 사용 |
| T자 주차 | R→D 최대 30 + 이동/조작 최대 30 + 진입 자세 최대 10 + 정렬각 최대 20 + 확인된 선 침범 최대 10 |
| 평행주차 | 동일 예산이지만 진입 자세/공간 허용 범위는 평행주차 조건으로 따로 검증 |

관측 가능한 여유 공간은 m 단위로 표시하되 초기 설계에서는 별도 추가 감점을 하지 않는다. 좌우 여유를 같게 만들라고 요구하지 않는다. 실제 문 열림 공간 등 맥락 없이 대칭을 정답으로 정하지 않는다.

### 연속 측정 항목

상한형 측정값은 방향을 정규화한 `x(t)`로 처리한다. 예: 속도/조향 속도는 크기, 양의 가속은 max(0,a), 감속은 max(0,−a). 하한형 여유는 부족분의 방향을 뒤집는다.

- 유효 구간의 초과 정도: `z(t) = max(0, (x(t) − B) / S)`, `S>0`.
- 0.3초 미만의 단독 이탈 구간은 제외한다. 큰 신호 공백을 가로질러 구간을 이어 붙이지 않는다.
- 누적 노출: `E = Σ z(t) × 실제 dt초`.
- 감점: `p = round_half_up(cap × min(1, E/tau))`, `tau>0`.
- 감속 관련 양의 감점 후보가 생겼으나 원인을 확인하지 못했다면, 해당 감속과 연결된 jerk 감점도 함께 막고 관련 그룹/총점을 보류한다. jerk 항목을 통해 급제동 과실 감점을 우회하지 않는다.
- `tau`는 전문가 자료로 보정한 고정 기준 노출시간이다. 현재 동작의 전체 길이로 나누지 않는다. 대기 시간을 늘려 기존 이탈 감점이 줄어드는 현상을 막는다.
- 속도 단계들은 겹치지 않는 시간 구간으로 합쳐 공통 40점 예산을 지킨다. 가속과 jerk는 같은 원인일 때 합산하지 않고 큰 쪽만 사용한다.

따라서 같은 프로필에서 초과 크기·초과 지속시간이 커질 때 감점은 감소하지 않는다. 이탈이 추가되지 않은 긴 정상 구간은 감점을 늘리거나 기존 감점을 희석하지 않는다. 0.3초 유지 시간도 시제품 잡음 억제 제안이며, 측정 주기 검증 후 조정한다.

### 주차의 고정 결과 항목

- 차량축과 칸축의 상대 각도는 축의 방향성이 없음을 고려해 180도 주기로 계산한다. `abs(((heading_vehicle-heading_slot+90) mod 180)-90)`.
- 진입 자세/정렬 오차는 전문가가 승인한 `B/S`로 정규화하여 `round_half_up(cap × min(1,초과 정도))`. 보정된 마지막 유효 정차 자세가 안정적으로 관측돼야 한다.
- 차체 외곽의 선 침범은 보정 오차 여유를 넘는 것이 확인될 때만 해당 상한을 적용한다. 모호하면 0점 감점이 아니라 보류다. 바운딩박스 겹침만으로 실제 접촉이나 과실을 선언하지 않는다.

### R→D 필수 항목 유지

실제 안정 기어의 R→D를 세며 R→N→D는 1회, D→R·중복 콜백·짧은 흔들림은 추가하지 않는다. 시제품 안정 유지 시간은 0.5초다. 기어 자체가 없는 DLP/INTERACTION 궤적의 방향 전환을 이 횟수의 정답으로 사용하지 않는다.

기존 가중 감점 기본값 `min(30,n×(n+1))`을 유지하면 0/1/2/3/4/5회는 **0/2/6/12/20/30점 감점**이다. 첫 전환부터 적용한다. 제품 요구인 가중 감점은 유지하되 이 수식은 기존 시제품 제안이며 안전 연구로 검증된 배점이라고 소개하지 않는다.

예를 들어 *확인된* 횟수 감점 12 + 이동 6 + 진입 0 + 정렬 4 + 침범 0이면 78점이다. 이는 수식 설명용 가상 예시이지 이번 데이터의 실측 성적이 아니다. 다른 필수 항목이 보류면 **78점도 산출하지 않고 총점 보류**, 확인된 횟수/항목만 표시한다. 누락 항목을 뺀 뒤 나머지를 100점으로 재정규화하지 않는다.

## 데이터 품질·전문가 검증·출시 전 게이트

- 신호별 단위·차종·측정/수신 시각·출처·품질·처리 버전을 보존한다. 속도 내부 단위 m/s, 핸들 각도와 앞바퀴 각도는 구분한다. radians↔degrees 및 좌우 부호를 자료별로 정규화한다.
- 필수 신호의 유효 비율 95% 이상, 연속 공백 1초 이하를 초기 품질 게이트로 제안한다. 전체 비율만 맞아도 되는 것이 아니라 진입/종료의 핵심 구간은 유효해야 한다. 시각/필수 항목이 부족하면 보류한다.
- 높은 주기 데이터를 낮은 주기로 평가할 때에는 인과적인 전처리로 맞춘다. 낮은 주기를 보간해 측정 정보가 늘었다고 주장하지 않는다. 장치/미분 처리기가 다르면 jerk 등의 기준을 직접 이식하지 않는다.
- 라벨은 최소 두 평가자가 독립적으로 작성한다. 동작 종류·시작/종료·단계·수용/개선/보류·원인·원래 근거를 함께 남긴다. 불일치는 이유를 정리하고 제3 검토로 조정한다.
- 운전자·실제 차량·기록일·세션/장면 단위로 분리한다. 인접 프레임이나 같은 차량 궤적을 무작위로 학습/시험에 나누지 않는다. DLP처럼 한 주차장 자료만 있으면 다른 주차장 일반화 검증을 했다고 말할 수 없다. 익명 참가자 ID가 운전자 ID임을 가정하지 않는다.

다음 수치는 **측정된 성능이 아닌 검증 목표 초안**이다.

| 항목 | 목표 초안 |
|---|---|
| 유형별 인식 precision / recall | 각각 95% / 90% 이상. 미확정으로 넘긴 정답 동작도 recall에서 누락으로 계산 |
| precision 불확실성 | 유형별 Wilson 95% 신뢰구간 하한 90% 이상 |
| 잠긴 시험 표본 | 유형별 최소 100개 사건을 계획하되, 충분성은 신뢰구간/조건별 분포로 판단 |
| 오피드백 | 시간당 1회 이하, 비대상 주행 시간과 조건도 함께 보고 |
| 실제 종료→종료 확인 | p95 2초 이내; 안정화 대기 포함 |
| 완료 확인→카드 데이터 발행 | p95 250ms 이내 |
| 카드 발행→TTS onStart | 발화 가능한 조건에서만 p95 1.5초 이내. 우선 오디오 대기는 별도 집계 |
| 전문가 점수 일치 | 100점 척도 MAE 10점 이하 목표. 전문가 간 weighted kappa 0.75 미만이면 평가표부터 재검토 |

평가 사건은 같은 유형·시간 구간 IoU 0.5 이상으로 일대일 매칭하는 초안을 사용한다. 잘못 분류한 사건은 예측 유형의 FP와 실제 유형의 FN으로 집계하고, 미확정을 제외해 recall을 부풀리지 않는다. 구간이 잘린 사건은 완료 평가에서 제외하되 수와 사유를 보고한다. 점수 검증에는 감지기가 예측한 유형/경계를 사용하며, 정답 구간을 미리 준 점수 엔진 검증은 별도의 상한 성능으로 표시한다.

전문가의 적용 가능 등급은 허용/경미 개선/큰 개선처럼 순서가 있는 등급으로 정해 weighted kappa를 계산한다. 정보 부족 보류는 나쁜 등급으로 순서화하지 않고 별도 일치율/비율을 보고한다. 연속 점수 차이는 MAE와 점수 분포를 함께 본다.

초기 수집 파일럿으로 강사 5명 × 7유형 × 20회 = 700건을 제안할 수 있지만, 이는 절차/라벨 검증용 규모이며 위 출시 검증 표본을 만족한다는 뜻은 아니다. 장소·차종·악조건·오인 사례를 추가하고 필요한 정답 사건/독립 시험 표본 수를 다시 산정한다. 공도에서 위험 조작을 유발하는 수집을 하지 않는다.
