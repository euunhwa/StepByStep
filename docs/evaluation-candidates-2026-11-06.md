# 제안된 API·평가 자료 검토

확인일: 2026-11-06 / Asia·Seoul. 사용자 제공 목록을 공식 자료와 대조했다. **목록 전체가 평가용 데이터셋은 아니다. 차량 입력 API, 평가 설계 참고, 데이터 저장소, 실제 궤적 자료를 구분해야 한다.** 이번 검토로 앱 점수 기준을 변경하거나 공개 자료로 검증 완료 처리하지 않았다.

## 사용 가능 범위

| 후보 | 실제 성격 | 인식용 활용 | 평가용 활용 | 현재 상태 |
|---|---|---|---|---|
| Pleos Vehicle SDK | 차량 서비스의 관측 API | 핸들·브레이크 등의 관측 입력 | 새 평가 자료를 직접 수집할 때 입력 채널 | 핸들 수신 구현/검증, 브레이크는 문서 존재만 확인·앱 미연결 |
| AAOS Car API | 차량 속성 관측 API | 속도/기어를 이용한 구간 인식 | 속도에서 가감속/jerk 등 측정값 산출 | 현재 속도/기어 수신 구현/검증 |
| Geotab ExceptionEvent/Scorecard | 규칙 위반 이벤트와 기간별 운전자 점수 설계 | 행동 분류 항목 참고 | 이벤트 빈도·가중치 설계 참고 | 공식 설명 조사만 수행. 계정 데이터/전문가 정답 미확보·미적용 |
| Zenodo REST API | 연구 자료 검색/다운로드 기반 | 적합한 실제 데이터셋을 찾아 확보 | 적합한 점수 라벨 자료를 찾아 확보 | API 자체는 모범/점수 데이터가 아님 |
| Dragon Lake Parking(DLP) | 실제 주차장 객체 궤적 데이터 | 저속 주차 구간/방향 변화/궤적 검증 후보 | 저속 속도/가속·기하 지표 보정의 보조 자료 후보 | 공개 메타데이터/README 확인. 원자료 미다운로드·미적용 |

## Pleos·AAOS: 관측값과 정답은 다르다

[Vehicle SDK 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)는 Vehicle Service 연결, capability/get/callback, Brake와 SteeringWheel 도메인을 설명한다. 문서 기준 버전은 SDK2.3.2/Service2.3.21이며 에뮬레이터 릴리스명2.1.0과 SDK 버전을 혼용하지 않는다. [Brake API 목록](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/brake/entry)에 지원 확인·현재 조회·등록/해제 API가 있다. 개별 get 페이지는 현재 도구에서 이름 외 상세 서명이 충분히 추출되지 않아 반환 범위/시각/강도를 검증했다고 주장하지 않는다.

현재 앱은 AAOS 속도/기어와 Pleos 핸들 원시값을 실제 콜백으로 받는다. 브레이크 상태는 VehicleFrame에 추가하지 않았고 실제 수신 시험도 하지 않았다. 브레이크 눌림을 수신하더라도 위험 회피인지 불필요한 급제동인지 자동으로 알 수 있다는 뜻은 아니다. 이 부분은 입력 범위에서 내린 해석이다. v0.8은 사용자 요청으로 원인/과실 판단과 관측 조작 점수를 분리했으며, 임의 관측 모드에서 수치 점수를 제공한다. 전문가/기존 정책의 원인 미확인 보류 및 필수 신호 누락 보류는 유지한다.

[AAOS 공식 속성 설명](https://developer.android.com/reference/android/car/VehiclePropertyIds#PERF_STEERING_ANGLE)에서 PERF_STEERING_ANGLE은 **앞바퀴 bicycle-model 각도**이며 운전자 핸들 각도와 독립이다. 현재 핸들45° 회전 후보 문턱이나 핸들 변화율 기준에 그대로 대입하면 안 된다. 속도는 m/s, 전진/후진 부호는 실제 이동 방향이며 기어와 독립일 수 있다. 차종별 capability/권한/단위/시각 검증이 먼저다.

## Geotab: 설계 참고로 가능

[ExceptionEvent](https://developers.geotab.com/myGeotab/apiReference/objects/ExceptionEvent/)는 규칙 위반 이벤트이며 시작/끝·기간·거리·운전자·위반 규칙 등의 구조를 제공한다. 공개 모범운전 정답셋이라는 설명은 아니다.

[Driver Safety Scorecard](https://support.geotab.com/help/mygeotab/reports/safety-reports/driver-safety-scorecard)는 급가속·급제동·급회전·안전벨트·과속·과도한 과속의 규칙 위반 빈도와 합계100%인 가중치로 운전자 점수를 계산하고 사용자가 가중치/분류 경계를 바꿀 수 있다고 설명한다. 따라서 이벤트 분류·가중 집계 설계에 참고할 수 있다. EasyCar의 ‘동작 한 번 종료→단계별 관측→즉시 점수’와 집계 단위가 달라 점수나 위험 분류를 그대로 옮기지 않는다. 이것은 문서 구조를 비교한 해석이다. API를 사용하거나 라이선스/계정 데이터를 확보한 상태가 아니며 현재 배점도 Geotab으로 보정하지 않았다.

## DLP: 가장 직접적인 데이터 후보지만 추가 정답 필요

[Zenodo 기록](https://zenodo.org/records/10084683)과 대체 [Dryad 공식 기록/README](https://datadryad.org/dataset/doi:10.5061/dryad.tht76hf5b), [저자 도구 저장소](https://github.com/MPC-Berkeley/dlp-dataset)를 대조했다. 드론으로 관측한 주차장 차량/보행자/자전거 궤적이며, Instance에 위치·방향·속도·가속도가 포함된다고 명시한다. JSON에는 Agent/Instance/Frame/Obstacle/Scene 구조가 설명돼 있다. 따라서 저속 이동·방향 변화·공간 궤적 지표를 검사하는 데 적합한 후보로 판단한다.

공개 필드 설명에서는 실제 D/R 기어, 핸들 각도, 브레이크 입력, 운전 강사의0~100점 모범 평가를 확인하지 못했다. 전체 원자료를 검수한 것은 아니다. 궤적의 전후진 방향 반전을 앱의 ‘안정 R→D 기어 횟수’ 정답과 동일시하지 않는다. 궤적으로 추정한 조향도 실제 핸들 센서 측정값이라고 표시하지 않는다.

원시 영상25fps와 가공 JSON 시계열의 실제 dt는 별도로 확인해야 한다. 속도/가속 분포를 구할 수 있어도 관측된 모든 운전이 모범/안전 운전이라는 뜻은 아니다. 사고 회피 상황이나 불량 조작이 섞일 수 있어 강사 검토를 거친 수용 사례를 골라야 평가 기준 보정에 사용할 수 있다.

이번에는 Zenodo 기록 본문 접근이 타임아웃됐고 REST 기록 주소는 웹 도구 접근 불가였다. 검색에 노출된 메타데이터와 Dryad의 공개 README/파일 목록은 확인했다. **대용량 원자료는 다운로드하지 않았고 학습·통계 적합·현재 채점에 사용하지 않았다.** 이전 조사에서의 접근 실패를 이번 확인과 구분한다. 원영상은 별도 요청 안내가 있고, 데이터와 저자 도구의 이용 조건도 각각 확인해야 한다. 도구 저장소에는 GPL-3.0 표시가 있으나 코드/데이터를 앱에 가져오지 않았다.

## 적용한다면 필요한 작업

1. SDK/AAOS 관측 입력을 시간·단위·품질과 함께 저장하고 인식 라벨과 평가 정답을 분리한다.
2. DLP 소규모 원자료의 실제 스키마·표본 주기·좌표계·차체/대상 공간을 확인한다. 같은 주행을 프레임만 나눠 학습/검증에 섞지 않는다.
3. 주차 시작/종료·유형을 라벨링하고 실제 보이는 기하 결과/저속 조작에 여러 평가자의 독립 평가를 추가한다. 미관측 기어·핸들·제동 원인은 추정 정답으로 만들지 않는다.
4. 강사 수용 사례의 공통 지표로 B/S/tau·배점을 보정하고 독립 주행에서 오탐·보류율·평가자 일치도를 검증한다. DLP만으로 일반 도로의 모든 회전/유턴/출발정지나 R→D 점수까지 검증됐다고 하지 않는다.
5. 실제 검증을 통과한 항목만 새 버전으로 활성화하고 임의 기준/검증 대기 항목과 구분한다. 현재7종·926표본의 임의 평가셋 표시는 유지한다.
