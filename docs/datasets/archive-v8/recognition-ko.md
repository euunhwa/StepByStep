# 인식용 데이터와 판별 조건

최종 갱신: 2026-11-06 / 앱0.8.0. 인식 규칙 r1은 v0.5와 같다. 가감속 완화와5초 표시는 v0.6에서 반영했고, v0.7에서는 메뉴와 분할 UI를 변경했다.

## 구현과 자료

코칭 시작 한 번으로 출발·정지·좌/우회전·유턴·T자/평행주차를 자동 관측한다. **급출발/급정지는 별도 인식 클래스가 아니다.** 출발/정지 구간을 먼저 인식하고 평가에서 가속·감속·jerk의 이탈을 분석한다.

| 자료 | 현재 사용 | 한계 |
|---|---|---|
| 자체 합성 파형45종 `app/src/main/assets/demo/signals/*.json` | 인식·종료·기어 안정화·곡선/차로 변경·공백 회귀 검증 | 실제 도로 정확도를 보장하지 않음 |
| 별도 `demo/truth-labels.json` | 시험 정답 비교 | 인식기는 이 파일을 읽지 않음 |
| comma2k19 NPY4개,159,680bytes, 속도/조향 각각4,974표본 | 형식·단위·시각 조사 | 기어/일곱 동작 라벨 없음. 학습·문턱 추정에 미사용 |
| localhost 차량 서비스 기록 | AAOS/Pleos 입력 연동 확인 | 에뮬레이터 자료. 실차·모범 주행 자료 아님 |

학습한 ML 모델은 없고 문턱은 시제품 규칙이다. 원본 설정은 `core/src/main/kotlin/com/easycar/core/Models.kt`의 **DetectionConfig**이며 현재 Kotlin 기본값으로 관리한다. 전이는 `CoachEngine.kt`, 전처리는 `Telemetry.kt`, 주차 유형은 `ParkingClassifier.kt`에 구현했다.

## 신호와 전처리

속도 m/s, 운전자 핸들 각도 degree, 진행 방향0~360degree, 시각ms를 사용한다. 핸들 각도와 앞바퀴 각도를 혼용하지 않는다. 이동 여부에는 속도의 절댓값, 전후진에는 실제 기어를 사용한다. 가속도=`Δ속도절댓값/Δt`, jerk=`Δ가속도/Δt`다.

각 신호의 값·측정/수신 시각·단위·출처·품질을 보존한다. 역순/중복 프레임을 거부하며 속도/핸들에는3표본 중앙값 필터를 적용한다(10Hz에서 최대 약200ms 필터 지연). 미분은 같은 D/R단과 실제 dt0.05~1초에서만 수행한다. 공백·기어 전환 때 필터를 초기화하며 수신 시각만으로 핸들 센서 변화율을 만들지 않는다.

| 설정 | 현재 값 | 의미 |
|---|---:|---|
| maxSignalAgeMs | 750ms | 오래된 신호 제외 |
| maxGapMs | 1,000ms | 초과 공백은 관측 중단/보류 |
| gearStableMs | 500ms | 기어 흔들림과 중복 횟수 억제 |
| stoppedMps | 0.15m/s =0.54km/h 이하 | 정차 후보 |
| movingMps | 0.7m/s =2.52km/h 이상 | 이동 후보 |
| standstillMs | 1,200ms | 정차 유지 확인 |
| preRollMs | 3,000ms | 진입 직전 맥락 보존 |

## 출발과 정지

- **출발**: 정차1.2초 확인 후 D단에서 속도≥0.7m/s이면 시작한다. 이동 시작 후4초를 관측하거나, 최소1초 이후 가속도<−0.3m/s²로 바뀌면 종료한다.
- **정지**: 속도≥2.0m/s(7.2km/h) 이동 이력을 확인한 뒤 가속도<−0.3m/s²이면 후보를 시작한다. 속도≤0.15m/s가1.2초 유지되면 종료한다.20초 내 정지 미확인 시 후보를 해제한다.
- −0.3m/s²는 **상황 탐지용**이다. 급감속 비교 경계−3.5m/s²와 다르며, 일반적인 출발/정지도 인식해야 한다.

## 좌/우회전과 유턴

| 단계 | 현재 조건 |
|---|---|
| 후보 시작 | D단, 속도≥0.7m/s, 핸들 각도 절댓값≥45° |
| 종료 후보 | 핸들 각도 절댓값<18°, 진행 방향 변화 속도≤5°/s가1초 유지, 전체 관측≥1.8초 |
| 좌회전 | 누적 진행 방향 변화 −120°~−55° |
| 우회전 | 누적 진행 방향 변화 +55°~+120° |
| 유턴 | 누적 진행 방향 변화 절댓값150°~210° |
| 유형 확정 품질 | 조향 관련 구간의 진행 방향 관측≥95%, 조향 부호 반전 없음, 평균 조향과 진행 방향 변화의 부호 일치 |
| 시간 초과 | 18초 안에 종료 미확인 시 확정 회전 대신 보류 |

**핸들45°는 회전 후보를 여는 문턱이다. 유턴/좌우 구분은 진행 방향의 누적 변화량으로 한다.** 현재 좌회전 음수/우회전 양수 규약이며 차종별 부호 검증이 필요하다.120~150° 등 경계 밖, S자 조향, 작은 차로 변경/곡선 변화, 방향 품질 부족은 UNKNOWN이다. 방향 없이 핸들 복원으로 후보를 닫을 수는 있지만 좌/우/유턴 유형은 확정하지 않는다.

실 입력 FusedLocation heading은 원시값 수신까지 확인했지만 시계/신뢰도 의미 검증 전이어서 LOW_CONFIDENCE다. 현재 실제 차량 서비스 입력에서 회전 유형이 보류될 수 있다.

## 주차: R단 진입부터 후보 관측

사용자가 제시한 **R단 진입을 주차 후보 시작**으로 사용한다. 실제 조건은 R이500ms 안정되고 속도 절댓값<2.2m/s(7.92km/h)일 때다. 검증된 공간 정보가 있으면 저속 D단 진입도 후보가 될 수 있다. D 전환으로 후보를 종료하지 않는다.

- P단과 정차가1.2초 유지되면 종료 후보로 평가한다. 단순 후진을 주차 완료로 확정하지 않도록 공간 근거를 검사한다.
- 검증된 도로축/주차칸축의 차이(180°축 기준)가0~15°이면 평행,75~90°이면 T자다. 대상 공간 연결, 기하 검증, 마지막 공간 관측 나이1.5초 이내 조건이 필요하다.
- 공간 없음·대상 변경·사선 공간이면 **주차 유형 미확인**이다. R만 보고 T자/평행까지 구분하지 않는다.
- 후보 속도>4.4m/s 또는5분 초과 시 중단한다. 완료 후 공간 밖 D단 이동1초가 확인되면 다음 주차를 다시 관측한다.
- 안정 R→D는1회, R→N→D도1회, D→R은 추가하지 않는다. 공간 근거가 없으면 관측 횟수만 보존하고 주차 확정 감점은 보류한다.

현재 실 차량 어댑터는 공간 공급원이 없다. 합성 데모만 공간 관측을 포함한다. 실제 입력의 R단 후보 관측과 T자/평행 확정·최종 정렬 점수의 가능 범위를 구분한다.

## 검증과 개선

관련 시험은 AutomaticCoachingTest, ImmediateFeedbackTest, EngineTest다. 공백·미확정 동작을 평가 데이터셋의100점으로 덮지 않는다. 완료 후5초만 평가 카드를 표시하고 다음 동작 관측을 계속하며 이전 기록은 복기에 보관한다.

개선에는 차종/운전자/날짜별 실제 주행과 시작·종료 라벨, 단순 후진/곡선/차로 변경 같은 비대상 사례가 필요하다. 주행/운전자별 독립 검증으로 유형별 정밀도·재현율·오탐·보류율과 경계 오차를 측정해야 한다. 현재 실차 독립 성능 수치는 없다.

## DLP 후보 검토 추가 · 2026-11-06

DLP의 공개 README는 위치·방향·속도·가속 궤적을 명시한다. 주차 후보/종료와 유형 라벨을 보완해 인식 검증에 쓸 수 있는 후보로 분류했다. 원자료를 확보하거나 현재 감지기에 적용하지는 않았다. 실제 기어·핸들 정답으로 간주하지 않는다. [공식 자료 대조와 확보 상태](../../evaluation-candidates-2026-11-06.md)를 참고한다.

README의 Scene/Instance, 선택 기어/현재 변속기 기어 등 용어 해석은 [자료별 문서 풀이](../readme-interpretation-ko.md)를 참고한다. 이번 문서 검토로 인식 입력이나 문턱을 바꾸지 않았다.

v0.8은 실시간 문구와 평가 표시/관측 점수 정책을 수정했다. DetectionConfig 및 회전/주차/출발정지 인식·종료 문턱은 변경하지 않았다.
