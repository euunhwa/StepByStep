# EasyCar — 차량 신호 자동 코칭 (0.8.0)

Pleos Connect **v2.1.0**용 Kotlin·Compose 시제품입니다. **코칭 시작 한 번 → 차량 서비스 신호 관측 → 일곱 동작 자동 인식 → 종료 판단 → 화면·음성 피드백** 경로를 사용합니다.

피드백 카드는 동작 완료 후 **5초** 표시하고 다음 동작 대기로 돌아갑니다. 기록과 대기 음성은 별도로 보존합니다. 임시 가속/감속 비교 경계는 **3.0/3.5m/s²**, 종방향 jerk는6.0m/s³이며 작은 초과의 누적 감점도 완화했습니다. 전문가 기준이 아닌 사용자 요청에 따른 시제품 조정입니다.

## 메뉴와 분할 화면

메뉴는 **홈·기록·설정** 세 개입니다. 성장 메뉴/화면을 제거하고 복기 메뉴와 기록 목록 이름을 기록으로 통일했습니다. 가용 폭900dp 미만 또는 높이500dp 미만에서는 분할 레이아웃을 사용합니다.

- 정차/시작 전: 간단한 차량 연결 상태와 코칭 시작, 세 메뉴를 표시합니다. 원시 신호·최근 기록·긴 설명은 홈에서 숨깁니다. 데모는 우측 상단에 유지합니다.
- 코칭 중: 메뉴를 숨기고 코칭 상태·점수·짧은 원인·종료 버튼만 표시합니다.5초 뒤 다음 동작 대기로 돌아갑니다. 데모가 일시정지된 경우에만 계속 버튼을 추가합니다.
- 실제 Pleos 분할은 오른쪽 가장자리 점 세 개 핸들을 왼쪽으로 끕니다. 시작/종료 버튼이 낮은 높이에서도 화면 안에 들어오도록 배치했습니다. [화면 동작 설명](../../split-screen-ko.md).

## 실행 경로

- 홈의 **코칭 시작**은 항상 AAOS/Pleos 차량 서비스 입력입니다. 이전 합성 시연 설정이 남아도 데모로 바뀌지 않습니다. 홈에서 속도·기어·핸들·진행 방향의 수신 상태를 볼 수 있습니다.
- **우측 상단 데모**는 제출용 합성 연속 주행 한 개(auto-drive,1,112프레임·111.1초)를 명시적으로 실행합니다. 데모 상태·기록은 합성 출처로 표시합니다. 일반 Android 데모 빌드에서도 이 버튼을 사용합니다.
- 정차 상태에서 설정의 차량 읽기 권한을 허용한 뒤 연결 다시 확인을 누릅니다. localhost 차량 조작은 [Virtual Console 안내](../../local-vehicle-control-ko.md)를 따릅니다. 에뮬레이터의 차량 서비스 신호이며, 실차 주행 자료를 확보했다는 뜻이 아닙니다.
- Pleos2.1.0 에뮬레이터는 PiP가 없어 오른쪽 가장자리 점 세 개 핸들을 왼쪽으로 끌어 내비 옆에 배치합니다. 작은 분할 영역에서 미니 코칭 화면이 나타납니다. 지원 기기의 시스템 PiP 코드는 별도로 제공합니다.

## 평가용 데이터셋은 임의로 만든 자료이며 개선이 필요합니다

사용자 요청에 따라 **7종 합성 참조 예제·926개 시계열 표본과 임시 B/S/tau**를 만들었습니다. 앱이 이 파일을 읽어 임시 코칭 점수를 계산합니다. 전문가 점수·실차/차종별 검증 자료가 아니며, 공개 자료로 학습하거나 보정한 모델도 아닙니다. 홈·설정·상세·미니 창에 임의 평가셋과 개선 필요를 표시하고 모든 새 점수는 **임시 N점**으로 구분합니다.

- 활성 데이터: `app/src/main/assets/evaluation/arbitrary-reference-v1.json`, `arbitrary-reference-episodes-v1.json`.
- 평가 정책: `evaluation-policy-prototype.json`. 전문가 검증 점수 모드는 꺼져 있고, 별도의 명시적 임시 비교 모드만 켜져 있습니다.
- 재생성: `python3 tools/generate_provisional_reference.py` (외부 데이터 다운로드·학습 없음).
- 배점: 출발100 / 정지100 / 회전 속도40·가감속30·조향30 / 주차 R→D30·이동30·진입10·정렬20·침범10.
- 이탈 크기·지속 노출은 고정 tau로 정규화하고 같은 원인의 가감속/jerk는 최댓값을 취합니다. R→D 시제품 배점은 `min(30,n*(n+1))`입니다. 운전 안전능력을 인증하는 기준이 아닙니다.

**필수 신호가 없으면 여전히 보류합니다.** 속도/기어 누락, 조향 측정 시각, 진행 방향 품질, 주차 공간/보정 영상 등 실제 원인을 표시합니다. 현재 임의 관측 모드는 급감속 상황의 원인이 없어도 측정된 조작 부드러움을 임시 점수로 계산하며, 과실/위험 회피 적절성은 판정하지 않습니다. 필수 신호가 부족하면 계속 총점을 보류합니다. 누락 항목을0점으로 만들거나 나머지를100점으로 환산하지 않습니다.

Pleos FusedLocation의 원시 heading은 받을 수 있지만 시계/confidence 의미 검증 전이라 품질 확인 대상으로 둡니다. 핸들 현재값은 수신·조회하며 수신 시각을 센서 측정 시각으로 바꾸지 않습니다. 대상 주차 공간 공급원·내장 어라운드뷰·Gleo 연동은 확보되지 않았습니다.

## 데이터셋은 어디에 쓰였나

[인식용·평가용 데이터셋 관리](README-ko.md)와 [데이터셋과 구현 매핑](../../dataset-implementation-v8-ko.md)에 확보 파일·실제 사용·미사용·한계를 정리했습니다.

| 자료 | 실제 사용 |
|---|---|
| comma2k19 소형 공개 예제4개 | 형식·단위·시각·해시 조사. 인식 학습/점수 기준 산출에는 미사용 |
| 자체 합성45개 파형 | 일곱 동작 인식·종료·기어·공백/미확정 코어 회귀 시험 |
| 임의 평가 참조7종·926표본 | 임시 비교 수치 로드와 시제품 점수 계산 |
| 제출용 합성 주행1개 | 우측 상단 데모에서 화면·음성·점수 시연 |
| localhost에서 수집한 차량 서비스 기록 | 데모 없이 실제 SDK/AAOS 입력이 앱까지 들어오는지 연동 검증 |

현재 인식은 규칙 기반이며 학습된 ML 모델이 아닙니다. Waymo 평가 라벨, 주차 주관 평가 자료, UAH-DriveSet 등은 개선 후보로 검토했지만 현재 모델/배점에 사용하지 않았습니다.

## 검증·빌드

JDK17, Gradle9.6.0, AGP9.5.0, Kotlin2.2.10, min28/target34/compile37.0입니다. Gradle 기본 작업자1개·CPU2개·JVM1.5GB로 제한했습니다.

```sh
./gradlew :core:test :app:testDemoDebugUnitTest :app:assembleDemoDebug :app:assemblePleosDebug
```

- Pleos APK: `app/build/outputs/apk/pleos/debug/app-pleos-debug.apk`
- 일반 Android APK: `app/build/outputs/apk/demo/debug/app-demo-debug.apk`
- 현재 검증·한계·실행 근거: [검증 기록](../../verification-v8-ko.md).

기록과 선택 영상은 기기 안에 저장합니다. 과거 기록은 원래 프로필/출처를 유지하며 새 평가셋으로 몰래 다시 채점하지 않습니다. 원문 기획은 `docs/requirements-ko.md`, 이전 데이터 조사·API 근거·v2/v3/v4 검증은 각 문서에 보존했습니다.

주행 중 표시는 `90점 (원인 : 급감속)`처럼 짧게 제공합니다.100점은 초록,80~99점은 주황,0~79점은 빨강이며 임의 평가셋 공지를 유지합니다. 기기/상황에 따라 실제 점수는 달라지며 예시90점을 고정 반환하지 않습니다.
