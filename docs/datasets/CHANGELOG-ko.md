# 데이터셋·기준 변경 이력

기준 변경은 해당 날짜의 항목을 추가하고 이전 값을 지우지 않는다. 문서와 실제 코드/JSON이 다르면 구현 원본을 확인한 뒤 함께 바로잡는다.

## 2026-11-10 · 인식1.0.2→1.0.3 · 주차 직전 저속 회전 이중 집계와 전진 주차

- **저속 회전 보류**: `recognition.json`에 `turnParkingHoldMs=8000`을 추가했다(이전: 키 없음). 구간 전체가 10km/h 이하인 좌·우회전을 8초 보류하고, R이 오면 주차에 합치고, 정차 중 P가 되면 전진 주차(`PARKING_UNKNOWN`, `forwardIn=1`, 유형·점수 보류)로, 10km/h 초과나 D에서 8초 경과면 회전으로 확정한다. 보류 중에 끝난 다른 결과(예: 대기 중 정지)는 회전 뒤에 대기했다가 판정과 함께 순서대로 기록해, 스윙 뒤 D에서 기다렸다 후진해도 이중 집계되지 않는다.
- 이전 동작(합성 신호 재현, [회귀 검사](../../core/src/test/kotlin/com/easycar/core/ParkingSwingDoubleCountTest.kt)): 스윙65°+후진 T자 주차 → 좌회전65° 결과와 T자 주차93° 결과가 함께 나옴(같은 회전 이중 집계). 전진 직각 주차 → 좌회전90°만 나오고 주차 결과 없음. 스윙40° 대조군은 이전에도 T자 주차 하나였다.
- **후진 조향 부호 집계**: T자/평행 판정에서 정차(0.15m/s 이하) 중인 R 표본의 핸들 부호를 세지 않는다. 이전: R 정차 중 반대로 핸들을 돌리면 한 방향 T자 주차가 S자로 보여 `PARKING_UNKNOWN`이 됐다(합성 신호 재현). JSON 수치 변경은 없다.
- 다른 문턱·평가 JSON·프로필·배점은 바꾸지 않았다. `manifest.json` id를 `document-datasets-1.0.3`으로, recognition SHA를 갱신했다. 과거 기록은 다시 계산하지 않는다. 8초는 공학 초기값이며 저속 회전의 확정·즉시 피드백이 최대 8초 늦어질 수 있다.
- 같은 날 인식·평가와 무관한 표시 기능을 추가했다: 주차 결과 상세의 궤적 재생(속도·기어·yaw 또는 핸들각으로 복원, 바퀴 방향·예상 경로·모범 경로), 차량 제원(`VehicleSpec`, 더 뉴 그랜저), 초보 T자 주차·평행 주차 합성 데모(`park-beginner`, `park-parallel`, 핸들을 초당 최대 360°로 돌림). 점수에는 쓰지 않는다.
- 실행한 검사: 코어 단위191개(새 회귀 19개 포함)·앱 단위 통과, debug/계측/release 빌드 성공. Pleos 에뮬레이터(2코어/3GB, read-only, 창 없음)에서 주차 데모가 T자 주차·R→D 2회·회전 결과 없음으로 기록되고 재생 화면이 그려지는 것을 확인했다.
- 미검증: 실차에서 저속 회전 보류의 오탐(주차가 아닌 저속 회전 후 P), 전진 주차의 유형 판정, 계측 검사 전체 재실행, 실제 Pleos 기기.

## 2026-11-09 · 앱0.13.2→0.13.3 · 기록 지연 로딩·빌드·APK 정리 (인식/평가 기준 변경 없음)

- 인식·평가 JSON, 프로필, 배점, 노출시간은 바꾸지 않았다(인식은 같은 날 1.0.2 그대로). 아래는 앱 저장·빌드·검사 변경이다.
- **기록 메모리**: 저장소의 기록 목록은 이제 원시 프레임 없이 유지하고, 프레임은 영상 복기처럼 필요한 화면에서만 DB에서 읽는다. 위 항목의 미검증 메모 "앱 시작 시 모든 기록의 프레임을 메모리에 올리는 동작은 그대로다"를 해소했다. v1 기록은 첫 로드 때 한 번 `frame_chunks`로 옮긴다. 프레임 값·순서·보존 범위는 같다.
- **화면**: 끝난 세션의 결과 화면을 앱 수준에서 한 번만 연다. 이전에는 Activity가 새로 만들어질 때마다 마지막 세션 결과로 다시 이동했다.
- **빌드**: JDK 17이 없으면 Gradle이 foojay로 내려받는다(`settings.gradle.kts`, `gradle-daemon-jvm.properties`). release는 R8 코드·리소스 축소를 켜고 Gson 저장 모델과 Pleos SDK를 유지한다. 검증 팩(`recognition-validation.json`, `evaluation-validation.json`)과 이전 `demo/signals`는 release APK에서 뺐다. 원본 파일과 :core 검사 경로는 그대로다. 서명 전 release APK 46.7MB→16.5MB.
- **기타**: deprecated API 경고 8개 정리(Android 15 전용 대체 API는 Pleos v2.1의 Android 14에서 쓸 수 없어 이유를 적고 억제). 문서·검증 로그의 개인 경로 `/Users/genius`를 `/Users/<user>`로 가렸다(기록 내용은 그대로). 버전 0.13.3(versionCode 19), Gleo 앱 스키마 [`schema.json`](../../app/src/pleos/assets/schema.json)의 `version`도 0.13.3으로 맞췄다(코어 검사가 `versionName`과의 일치를 확인).
- **오래된 계측 검사 정리**: `DemoFlowTest`와 `ImmediateCoachFlowTest`가 상단 고정 데모 버튼에 스크롤 동작을 쓰거나, yaw가 없는 이전 `left` 데모·이전 엔진 수치(T자 R→D 3회/12점)를 기대하던 부분을 현재 문서 데모 기준으로 고쳤다.
- 실행한 검사: 시스템 JDK 25만 있는 상태에서 JDK 17 자동 다운로드 후 빌드 성공. 코어172·앱21 단위 통과, 경고0. Pleos 에뮬레이터(2코어/3GB, read-only)에서 계측30개 중29개 통과. 실패1개(`FeedbackScoreUiTest`, "No compose hierarchies")는 단독 재실행 통과. 세션 종료 직후 실행되는 검사에서 위치를 바꿔 나타나는 순서 의존 현상이며 변경 전(HEAD)에도 `SplitUiFlowTest`에서 같은 오류를 확인했다. 축소 release APK(검사용 debug 키 서명)를 디버그 기록 위에 설치해 기존 기록 표시, 차량 연결·핸들 신호 수신, 7개 데모 동작 결과(각 100)와 요약을 확인했고 앱 충돌 로그는 없었다.
- 미검증: 전용 키로 서명한 0.13.3 release, 실제 Pleos 기기, 위 순서 의존 현상의 근본 원인(Pleos 홈의 분할 화면 배치로 추정, 미확인).

## 2026-11-09 · 인식1.0.1→1.0.2 · 감속으로 끊긴 회전과 출차 기록 · 기록 저장 형식

- **회전 이어 붙이기**: `recognition.json`에 `turnPauseMaxMs=10000`을 추가했다(이전: 키 없음). 1.0.1에서는 회전 중 속도가0.7m/s 아래로 내려가면 회전 구간을 즉시 끝냈고, 60° 미만으로 남은 앞뒤 반쪽은 기록 없이 버려져 보행자 양보 같은 감속 회전이 사라졌다(합성 신호로 재현: 90° 좌회전 중1초0.5m/s → 좌회전 결과 없음). 이제 한 방향·60° 미만 구간은10초 보관하고 같은 부호 bump가 이어지면 합쳐 분류한다. 다른 문턱(yaw bump/peak·60~120°·150~210°·30초)은 바꾸지 않았다. 10초는 공학 초기값이며 근거 문헌 수치가 아니다.
- **출차 제외**: 안정된 P에서 R로 시작한 주차 구간이 D·10km/h 초과로 끝나면 `PARKING_UNKNOWN` 보류를 남기지 않는다(이전: 주차 칸에서 빠져나올 때마다 보류 기록). D에서 시작한 주차 시도의 속도 이탈과5분 초과는 이전처럼 보류한다. JSON 수치 변경은 없다.
- 평가 JSON·프로필·배점·노출시간은 바꾸지 않았다. `manifest.json`의 id를 `document-datasets-1.0.2`로, recognition SHA를 갱신했다. 과거 기록은 다시 계산하지 않으며 저장된 인식 버전을 유지한다.
- **기록 저장 형식(앱 DB v1→v2)**: 실행 신호 프레임을 세션 JSON에서 분리해 `frame_chunks` 테이블에 추가 기록한다. 이전에는2초마다 최대36,000프레임 전체를 JSON으로 다시 썼다(데스크톱 JVM 측정: 36,000프레임 ≈2,600만 자, 직렬화1회123ms). Room 자동 마이그레이션이며 v1 기록은 그대로 읽고 다음 저장 때 새 형식으로 옮긴다. 프레임 값·순서·보존 범위(최근36,000)는 바꾸지 않았다.
- 실행한 검사: 코어 단위172개(새 회귀7개 포함)·앱 단위21개 통과, `assemblePleosDebug`/계측 APK 빌드 성공. Pleos 에뮬레이터(2코어/3GB, read-only)에서 계측29개 중25개 통과. 실패4개(`DemoFlowTest`, `ImmediateCoachFlowTest`3개)는 변경 전 기준에서도 같은 오류로 실패하던 기존 검사다(고정 버튼에 스크롤 동작, yaw 없는 이전 `left.json` 데모 사용). 이전 HEAD 디버그 앱으로 만든 v1 DB를 새 앱으로 덮어 설치해 v2 마이그레이션, 기존 기록 보존, 새 기록의 청크 저장(페이로드814KB→17KB, 896프레임/53청크)을 확인했다.
- 미검증: 실차 주행에서의 회전 이어 붙이기 정확도와10초 값의 타당성, 실제 Pleos 기기에서1시간 세션의 저장 부하, release 서명 APK(0.13.2)에서의 업그레이드. 앱 시작 시 모든 기록의 프레임을 메모리에 올리는 동작은 그대로다.

## 2026-11-07 · 앱0.13.2 · 사용자 화면의 기술 문구 정리

- 사용자 지정 범위대로 홈 차량 신호 카드의 제목과 속도·기어·핸들 각도·진행 방향을 유지하고 나머지 개발 설명을 숨겼다. 코칭·작은 창·기록/상세·질문·영상의 yaw/jerk·내부 코드·버전·전문 수치/단위·JSON 도구·원문 진단을 일상어로 바꿨다. 공통 하단은 짧은 연습 참고 안내로 정리했다.
- **설정 화면은 그대로 유지**했다. 원시 신호·감점·보류·프로필/정책·영상 근거는 저장 자료에 보존하며 사용자 표시 층만 바꿨다. 신호가 없거나 보류인 결과를 정상/0점으로 바꾸지 않는다.
- 보류 코칭의 다시 듣기가 기술 원문을 그대로 읽지 않게 바꾸고 질문 화면의 답변 듣기도 친숙한 문장을 사용한다. 외부 Gleo의 기계 응답 규격과 원본 저장 점수는 유지한다.
- 인식/평가 JSON·프로필·각도/지속시간/감점 기준·완료 카드 노출시간은 바꾸지 않았다. 설정 소스 동일성과 활성 자료 해시를 확인한다. 검증 결과·화면은 [0.13.2 검증](../validation/friendly-ui-v0132.json)에 기록한다.
