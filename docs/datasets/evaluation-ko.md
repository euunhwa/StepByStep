# 평가용 데이터와 채점 기준

## 0.13.1 현재 적용 범위

사용자 요청으로 별도 주차 녹화·통합 배점은 현재 앱에서 제외했다. 활성 평가는 이전 `evaluation-document-1.0` / `document-derived-1.0`이며 기존 주차 동작의 전후진/시간 기준과 영상 복기를 유지한다.0.13 실험 기록은 읽기 호환으로 보존하고 과거 점수를 재계산하지 않는다. 현대/Pleos에서 승인된 보정 AVM 탑뷰와 시각·차체 외곽 정보가 제공되면 별도 검증 후 재검토한다.

## 0.13.0 보관 실험 · 현재 미적용

0.13.0 실험은 `parking-outcome-draft-1.0`을 사용했으며 현재 앱에서 적용하지 않는다. [보관 정책 JSON](../../experimental/parking-capture-v013/app/src/main/assets/profiles/parking-outcome-v1.json), [보관 채점 구현](../../experimental/parking-capture-v013/core/src/main/kotlin/com/easycar/core/ParkingOutcome.kt), [사용법·입력·픽셀 검증](../parking-capture-ko.md). 기존 `evaluation-document-1.0` / `document-derived-1.0`과 그 과거 T자/평행 점수는 변경하지 않는다. 당시 정책은 T/평행 분류가 필요 없는 일반 주차용이었다. 지금은 과거 버전 기록으로 조회하며 재채점하지 않는다.

`점수 = max(0,100 − 전환 감점 − 기울어짐 감점 − 좌우 감점 − 앞뒤 감점 − 침범 감점 − 침범 점수상한 조정)`

| 항목 | 실행 값과 수식 |
|---|---|
| R→D | 기본 허용1회, `min(30,max(0,횟수−1)×5)`점. 기존 평행주차 허용2회를 이 경로에 적용하지 않는다. |
| 기울어짐 | 차량/칸 긴 축 차이≤3°:0점,3°초과~8°:5점,8°초과:10점 |
| 좌우 치우침 | 중심의 횡방향 거리/칸 전체 폭≤0.10:0점,0.10초과~0.20:5점,0.20초과:10점 |
| 앞뒤 치우침 | 중심의 종방향 거리/칸 전체 길이≤0.15:0점,0.15초과~0.30:5점,0.30초과:10점 |
| 경계 침범 | 네 경계 중 하나라도 차체 최소 여유<−2px이면20점, 결과59점 초과 시59점까지 추가 감점하고 별도 원인을 표시 |
| 불확실 경계 | 최소 여유가−2px~+2px이면 포함 여부 불확실로 점수 보류 |

프레임은 긴 변 최대640px로 분석하므로2px 오차 문턱도 그 분석 해상도의 값이다. 물리 거리나 차량별 허용 오차로 검증된 값이 아니다. m/px가 없는 이 경로에서 cm/m를 생성하지 않는다. 차체가 네 경계 모두 안쪽인지 검사하므로 측면만 양호한 앞/뒤 돌출을 통과시키지 않는다. 침범59점 상한은 개발자가 정한 초안으로, 시험 합격·안전 판정이 아니다.

영상 저장 실패·전체 속도/기어 누락·시작/중간 공백·이동 미관측·P정차 자동완료 미확인·P전 정차 부족·영상시각 연결 실패·보정/전체 경계 부족·정차 구간 변화·선 근거 부족·시스템/사용자 중단이면 점수는null이고 이유를 저장한다. 관측이 완전한 전환 감점은 보류 기록에도 표시할 수 있지만 통합 점수로 공개하지 않는다. 조건이 충족된 첫 분석만 점수를 공개하며 공개한 점수는 다시 분석해 바꾸지 않는다.

배점은 **합성 자료로 동작만 검증한 임시 기준**이다. 숙련자/전문가 평가, 실차 AVM, 조명·스티칭·차종별 오차, 장애물·연석 접촉은 미검증이다. 이 기준의 개선과 실측 자료 확보가 필요하다. 이전 기록을 새 기준으로 몰래 다시 채점하지 않는다.

아래는 기존 일반 코칭·영상 복기의 기준 이력이다.

앱0.10.0은 영상 복기 근거만 `parking-vision-2.0`으로 개선했다. [영상의 거리·경계·구간 조건](../parking-video-analysis-ko.md)은 관측용이며 새 감점 기준이 아니다. 보정/대상 칸을 바꾸어도 저장된 동작 점수·측정값·피드백을 재계산하지 않는다. 이 문서의 활성 배점·평가 JSON·프로필 버전과 미관측 공간 완성도 보류는 유지한다.

## 데이터의 성격

첨부 문헌 명세의 수치를 초기 평가 경계로 사용했다. 기존7종926표본·B/S/tau 임의 참조셋0.2는 새 코칭에서 사용하지 않는다. 새21개 데이터는 **경계값과 배점 계산을 검사하는 임의 합성 지표 벡터**이며, 실제 시간에 따른 차량 운동이나 전문가 모범운전 모집단이 아니다. 새 일곱 동작 데모도 합성 검증용이다. 학습·분위수 추정·회귀 피팅·전문가 점수 수집을 수행하지 않았다.

앱 고지: “문헌 기반 평가 초안 · 임의 배점과 합성 검증 데이터는 개선이 필요합니다. 전문가·실차 검증 전 조작 지표 점수예요.” 새 결과에 `PROVISIONAL`, 프로필/정책 버전, 근거·측정값·미관측 항목을 저장한다. 문헌의 편안함·선호값을 보편적 안전성 경계로 확정하지 않는다.

0.9.3 촬영은8088에서 DDS·차량 서비스를 거쳐 받은 속도·기어·핸들을 평가 입력에 사용한다. DEBUG 에뮬레이터의 yaw만 축거2.7m·조향비15의 명시적 모델로 계산하며 출처는 `EMULATOR_BICYCLE_MODEL_NOT_SENSOR`다. 이에 따른 횡가속 `v×yaw`도 모델 추정값이며 센서 실측이 아니다. 실제 차량에는 이 모델을 활성화하지 않는다. [입력과 모델 예외](recognition-ko.md).

## 실행 경계와 수식

| 항목 | 감점 없음 | 주의 −5 | 위험 −7 | 적용 방식 |
|---|---|---|---|---|
| 가속 | ≤2m/s² | >2, <10/3.6 | ≥10/3.6=2.777… | 연속600ms. 문서 표의2.78은 반올림값 |
| 감속 절댓값 | ≤2m/s² | >2, ≤3.5 | >3.5 | 연속600ms |
| 종방향 jerk 절댓값 | ≤0.9m/s³ | >0.9, ≤1.5 | >1.5 | 연속600ms, 값없는 구간은 연결하지 않음 |
| 회전 피크 횡가속 | ≤0.25g | >0.25, ≤0.4g | >0.4g | g=9.80665m/s². 전용 차량 센서 우선, 없으면 정렬된 v×yaw 추정 |
| 급회전/급유턴 | 인식의 고속·시간 조건 미해당 | — | 해당 시7 | 횡가속 감점과 큰 값만 적용 |
| 주차 R→D | T자1회/평행2회 이내 | 초과 회당5 | — | `(횟수−허용횟수).coerceAtLeast(0)×5`, 최대100 |
| 주차 시간 | ≤120초 | — | 초과120초 블록당10 | `ceil(max(0,시간−120초)/120초)×10`, 최대100 |

`점수 = 100 − min(100, 가감속 그룹 + jerk + 회전 그룹 + 주차 횟수 + 주차 시간)`.
가속·감속은 같은 동작 안에서 큰 감점 한 번, 횡가속·고속 회전도 큰 감점 한 번만 적용한다. jerk는 별도다. 이는 중복 감점 억제를 위한 앱 설계안으로 검증된 사고 가중치가 아니다. 초과시간은600ms 충족 여부를 판정하며 기존 S/tau 노출량 적분은 사용하지 않는다. 예: 가속2.4 + jerk1.2가 각각600ms 지속하면100−5−5=90점. T자 R→D3회는100−(3−1)×5=90점(다른 감점이 없을 때).

인식 급가속2.222…·급출발2.777…·급감속3.888…와 위 평가 경계는 다른 목적이다. 감속3.6은 위험 감점 대상이지만 급정지 인식 문턱3.888…에는 미달할 수 있다. 신호가 없으면 이를0이나 정상으로 처리하지 않는다. 속도·기어 충족률95%, 이동 중 미분 준비300ms 이후 가감속/jerk 충족률95%가 필요하다. 회전·주차는 yaw 충족률95%와 유형 근거도 필요하며 부족하면 전체 조작 점수를 보류한다. 순간 스파이크는600ms 조건으로 감점하지 않지만 회전 횡가속은 문서의 피크 기준이다.

현재 출력은 **관측된 조작 항목의 점수**다. 안전 맥락과 주차 완성도 같은 미관측 항목은 passed=null/보류로 별도 저장하며 총점100이 안전성·주차 성공의100점을 뜻하지 않는다. 제동 원인·과실·위험 회피 적절성을 판정하지 않는다.

## 0.9.3 촬영의 점수와 색상

[화면 색상](../../app/src/main/java/com/example/easycar/ui/FeedbackCard.kt)은100점 파랑,80~99점 주황,0~79점 빨강이다. 미평가를0점으로 바꾸지 않는다. 색상 변경은 평가 경계나 감점 크기를 바꾸지 않는다.

현재8088 제어 API는 정수 km/h와 정수 핸들 각도를 받는다. 이 양자화 입력으로 정확한90/85점을 가감속 경계에 맞추는 대신, 기존 주차 횟수 식으로 여러 점수를 만드는8장면을 준비했다. 장면마다 새 라이브 세션을 시작하고 실제 `motion`/`frames` 수신 후 입력을 진행한다. 목표 점수는 촬영 입력 설계 메타데이터이며 앱에 정답이나 고정 점수로 전달하지 않는다.

| 장면 | 오프라인 예상 점수 | 감점 근거 |
|---|---|---|
| 출발·좌회전·우회전·유턴·정지 | 각각100 | 해당 입력에서 감점 조건 없음 |
| T자 주차 | 60 | R→D9회: `100−(9−1)×5` |
| 평행주차 | 90 | R→D4회: `100−(4−2)×5` |
| 추가 T자 주차 | 85 | R→D4회: `100−(4−1)×5` |

일곱 유형에 T자 주차 한 장면을 추가한 구성이다. 다른 감점이 생기거나 필수 입력이 누락되면 실제 점수는 달라지거나 보류될 수 있다. 프로필·평가 JSON·감점 수식은 변경하지 않았고 과거 기록을 재채점하지 않는다. 코어114개·앱 단위5개 검사와 빌드는 통과했다. DEBUG 모델 입력의 기어/핸들 current read 빈도를 명목200ms 간격으로 높이고 실차500ms 및 신선도750ms는 유지한다. 촬영 드라이버의 `consoleSteeringDeg = −theorySteeringDeg`는 콘솔→SDK 부호 매핑이며 감점이나 동작 판정 결과를 보정하는 처리가 아니다. 최종8장면의 실제 점수·영상·음성 검수는 [8088 촬영 검증](../console-capture-ko.md)에 별도로 기록한다.

## 적용하지 않은 항목

- 기존 조향 속도160/120°/s, 정렬3°, 진입15°, 속도4/3.5/4m/s 등 임의 허용값: 활성 평가에서 제외.
- 안전 위반−10은 설정값만 보유. 방향지시등·교차로·보행자·신호·제한속도 등이 없으므로 위반을 만들거나 정상으로 채우지 않는다.
- 면허시험 합격/실격, 제한속도+10, 연석 접촉: 첨부 문서가 원문 법령 미대조라고 밝힌 항목. 법적 판정 미구현, 차량 관측도 부족.
- 유턴 `v≤√(0.2gR)`: 실제 반경R 미수신으로 보류. R=6m·12km/h를 보편 상한으로 쓰지 않는다.
- 정렬·구획·연석·full-lock·차종별 조향비/휠베이스: 신호/보정이 없어 보류. 기존 영상 분석기는 기록에서 별도로 볼 수 있지만 새 기동 점수를 구 채점기로 재채점하지 않는다.
- UBI100km 정규화/카테고리15·25·30·30·맥락 가중·짧은 주행 축소: 신뢰할 거리/제한속도/맥락·사전 평균 계수가 통합되지 않아 보류. 기록의 숫자는 기존과 같이 **기동 점수의 산술평균**이며 UBI 안전점수로 표시하지 않는다.
- 지수 페널티: 실차에 보정된 M/p 미확보로 미사용. 조향 보정−7: 차종 보정/검증 기준 없어 미사용.

## 버전·기존 자료

새 앱은 기존 기록을 보존하고 다시 채점하지 않는다. 구 버전 데모 기록의 이어하기는 프로필 버전 불일치로 막고 조회만 허용한다. 새 프로필의 legacy scoring 필드는 기존 저장 형식 호환용으로 모든 밴드 가중치/감점0으로 두며 새 엔진에서는 읽지 않는다. 새 정책 없는 새 프로필은 예외를 내므로 구 채점기로의 우회가 없다.
