# 세 메뉴와 분할 화면 · EasyCar0.8.0

메뉴는 홈·기록·설정 세 개다. 성장 메뉴와 성장 화면을 제거했고 기록 목록/이동 동작의 이름도 기록으로 정리했다. 저장된 주행 데이터는 삭제하지 않았다.

## 크기에 따른 배치

앱에 실제 할당된 폭<900dp 또는 높이<500dp이면 간결한 레이아웃으로 바뀐다. 실제 Pleos는 기본 넓은 창도 시스템의 multi-window로 보고하므로 그 플래그만으로 분할 전용 화면을 선택하지 않는다. 기존 기본 앱 창은 약1682×1210dp, 내비와 나눈 창은 약841×1210dp로 확인했다.

| 상태 | 표시 |
|---|---|
| 정차·시작 전 | 상단 홈/기록/설정, 차량 연결 상태, 코칭 시작, 우측 상단 데모, 임의 평가셋 안내 |
| 낮은 높이의 시작 전 | 긴 제목과 카드를 생략하고 연결 요약·시작 버튼을 직접 표시 |
| 코칭 대기 | 입력 출처, 다음 동작 대기, 종료 버튼 |
| 동작 완료 후 | 입력 출처, 동작 이름, 짧은 감점 원인, 관측 점수 또는 평가 대기, 종료 버튼 |
| 완료 후5초 | 이전 카드를 치우고 다음 동작 대기. 기록과 음성 대기열 보존 |
| 데모 일시정지 | 계속 버튼과 종료 버튼 |
| 주행 제한 중 코칭 미시작 | 주행 집중 안내. 시작/기록/설정 조작 제한 |

원시 신호 표, 최근 기록, 그래프, 일곱 동작 목록, 반복적인 작은 창 전환 버튼은 코칭용 분할 화면에 표시하지 않는다. 기록과 설정은 정차 중 해당 메뉴를 열어 확인한다. 임의 평가셋/개선 필요 공지는 짧게 유지한다. 매우 작은 PiP 크기에서는 터치 버튼을 넣지 않고 시스템 동작을 사용한다.

## Pleos에서 사용

오른쪽 가장자리 점 세 개 핸들을 왼쪽으로 끌어 내비 옆에 배치한다. 화면을 줄이기 전후 같은 서비스 세션이 분석을 계속한다. 작은 창과 전체 창을 오갈 때 코칭을 다시 시작하지 않는다. Pleos2.1.0 에뮬레이터는 PiP feature가 없어 떠있는 PiP 성공을 주장하지 않는다.

## 검증 범위

앱 JVM 표시 정책 시험, 앱에 실제 제약 크기를 부여한 Compose 흐름 시험, 기존 피드백 만료/미니 경계 시험 및 실제 시스템 분할 화면 확인을 구분해 [검증 문서](verification-ko.md)에 결과를 기록한다. 인식/평가 기준은 변경하지 않았다. [인식용](datasets/recognition-ko.md)과 [평가용](datasets/evaluation-ko.md) 문서는 같은 활성 버전을 유지한다.

v0.8에서는 관측 중 제목/대기 설명/긴 피드백을 제거했다. 점수 색상은100 초록,80~99 주황,79 이하 빨강이다. 임의 평가셋 공지는 유지하며 실제 정책 변경은 평가용 관리 문서를 따른다.
