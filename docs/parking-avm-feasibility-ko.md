# 주차 녹화·최종 배치 채점 구현 가능성 검토

2026-11-07 · EasyCar0.12.0 · Pleos Connect v2.1.0 에뮬레이터/사용자10. 이 검토에서는 제품 코드·권한·차량 제어값·저장 점수를 변경하지 않았다.

## 결론

요청한 `주차 시작부터 녹화 → 전후진 횟수와 최종 배치로 통합 채점 → 점수·영상 저장`의 앱 내부 기능은 구현 가능하다. 현재 일반 앱 구성을 그대로 사용한 실차 내장 어라운드뷰 자동 녹화는 지원 경로가 확보되지 않아 완료를 확약할 수 없다. 가장 먼저 해결할 조건은 OEM/플랫폼이 허용하는 어라운드뷰 영상 입력이다.

## 실제 확인한 사실

- EVS 서비스와 `/dev/video10~13` 네 카메라 장치가 존재한다. CarEvsService는 REARVIEW/FRONTVIEW/LEFTVIEW/RIGHTVIEW 상태 머신을 가진다.
- EVS에 640×360 프레임 수신·반환 통계가 있다. 영상 소스가 없다는 결론은 틀리다. 이 통계는 EasyCar에서 녹화했거나 합성 탑뷰를 받았다는 증거는 아니다.
- 일반 카메라 서비스는 전면 카메라1개를 공개한다. 이를 어라운드뷰 입력으로 취급할 근거는 없다.
- `USE_CAR_EVS_CAMERA`와 `MONITOR_CAR_EVS_STATUS`는 `signature|privileged`, `SYSTEM_CAMERA`는 `signature|privileged|role`이다. EVS 시스템 앱은 관련 권한을 보유한다. EasyCar는 일반 `/data/app` 앱으로 설치됐고 해당 권한을 요청하지 않는다. 일반 CAMERA 런타임 허용만으로 EVS 권한이 생기는 구조가 아니다.
- 실제 사용하는 Vehicle SDK2.3.2 AAR와 Vehicle 진입점 API에서 카메라·EVS·영상 프레임 수신 기능을 찾지 못했다. 별도의 미공개/별도 제공 SDK나 OEM 연동 가능성을 부정하는 뜻은 아니다.
- MediaProjection 서비스는 존재한다. 검토 시 활성 EVS 창이 없어 해당 화면의 보호 플래그와 화면 녹화 성공 여부는 확인하지 않았다. 직접 프레임 열기나 MediaProjection 녹화 성공을 시험한 것으로 표시하지 않는다.

구조화된 근거: [검토 JSON](validation/parking-avm-feasibility-v012.json).

## 입력 경로별 판단

| 경로 | 판단 |
|---|---|
| 승인된 AVM 프레임/녹화 API | 우선 확인할 제품 경로. 합성 탑뷰 또는 승인된 녹화 파일, 시각 정보와 보정 데이터 제공 여부 확인 필요 |
| 일반 앱의 직접 EVS 카메라 이용 | 현재 SDK·권한 구성으로 확보되지 않음. 표준 플랫폼 API를 통한 지원 경로 필요 |
| MediaProjection으로 AVM 화면 녹화 | 조건부 대안. 세션별 사용자 동의·foreground service·화면 가시성·보호 여부·Pleos 지원 범위를 확인해야 함. 현재 성공 미검증 |
| 합성/재생 영상으로 전체 흐름 개발 | 지금 가능. 실제 신호와의 동기화, 반복 횟수, MP4 저장, 종료 구간 분석, 점수·근거 저장을 검증하는 개발 경로 |
| 외부에서 녹화한 실측 탑뷰 가져오기 | 분석 정확도 검증에 활용 가능. 앱이 주차 시작부터 자동 녹화했다는 의미는 아님 |

ADB나 호스트 녹화 도구를 이용한 개발용 화면 촬영은 일반 앱의 배포 가능한 카메라 입력 API를 검증하지 않는다. 보호된 화면이 캡처 가능하다고 가정하지 않는다.

## 앱 내부 구현 범위

1. 주차 시작/종료를 일반 주행 이벤트와 분리한 주차 세션으로 관리한다. 시작 버튼은 후진 전 준비 구간도 녹화하기 위한 초기 제품안이다. 자동 시작을 선택하면 시작 근거와 누락될 수 있는 준비 구간을 명시해야 한다.
2. 영상 기록 시작 완료를 확인한 후 세션을 시작하고, 차량 신호와 영상의 단조 시계를 매핑한다. 영상이 없으면 녹화 중으로 표시하지 않는다.
3. 안정된 R/D 전환을 기록한다. 현재 규칙은 R→D를1회로 세므로 사용자가 말한 ‘왕복’ 정의와 허용 횟수를 제품 규칙으로 확정해야 한다. 영상의 최종 배치 점수는 T자/평행 운동 패턴 확정에 종속시키지 않는다.
4. P·정차를 확인할 때 영상 종료와 최종 유효 정차 구간을 함께 보존한다. 영상 중단·누락·시각 불일치가 있으면 불완전 기록과 원인을 남긴다.
5. 주차칸 전체 경계와 실제 차량 외곽을 비교해 포함·각도·좌우/앞뒤 치우침을 측정한다. 현재 검출기는 좌우 두 선 중심이어서 앞뒤를 포함한 전체 배치 판정은 추가 구현이 필요하다. 합성 차량 좌표를 실측 영상에 재사용하지 않는다.
6. `100 − 왕복 감점 − 최종 배치 감점` 정책을 별도 버전으로 정의한다. 감점 문턱·허용 오차·상한은 검증용 초안과 실측/전문가 검증을 구분한다. 근거 부족을 감점0으로 바꾸지 않는다.
7. 전체 MP4, 판정 구간/장면, 차량 신호, 개별 감점, 보정·정책 버전을 같은 세션에 저장한다. 저장 실패·디스크 부족·프로세스 종료를 처리하고 기존 점수를 자동 재채점하지 않는다.

## 권장 검증 순서

첫 단계는 제품 영상 입력 경로 확정이다. SDK/승인된 서비스, 일반 앱 허용 여부, 녹화·저장·분석 허용 범위, 합성 탑뷰 제공 여부와 보정·시각 정보를 확인해야 한다. 이후 개발 입력으로 전체 세션 흐름을 구현하고, 실측 어라운드뷰로 기하 분석을 검증한 다음 대상 차량에서 장시간 녹화·종료·복구를 시험한다.

개발 회귀에는 정렬·좌우/앞뒤 침범·회전·다중 주차칸·선 가림·선 없음·밝기 변화·프레임 누락·동기화 오류·정차 전 P 전환·짧은 기어 튐·녹화 중단·저장 실패를 포함한다. 실제 영상 입력 계약이 없으면 제품의 실제 자동 녹화 완료로 표시하지 않는다.

## 공식 근거

- [Pleos 하드웨어 접근 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/platform-api-architecture): 직접 하드웨어 접근을 제한하고 표준 플랫폼 API를 사용하도록 명시한다.
- [Vehicle SDK](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/intro): 현재 공개 도메인과 서비스 연결 구조.
- [Android EVS 구조](https://source.android.com/docs/automotive/camera/evs/camera-hal): EVS 카메라·매니저·표시 구조와 OEM 구현 역할.
- [MediaProjection](https://developer.android.com/media/grow/media-projection): 세션별 동의, foreground service, 녹화 표면과 중단 콜백.
- [FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE): 보호된 창의 캡처 제한.

## 0.13.0 구현 후속

이 문서는0.12 시점의 검토 기록이다. 이후 사용자 승인 MediaProjection 녹화·전후진 집계·최종 배치의 별도 임시 점수·MP4 저장을 구현했다. 당시 범위와 실제/합성 검증 이력은 [주차 녹화 문서](parking-capture-ko.md)를 따른다. EVS 직접 접근 권한과 실제 AVM 탑뷰 보정은 여전히 별도이며 일반 화면 녹화 성공으로 대체하지 않는다.

## 0.13.1 적용 결정

사용자 요청으로 실제 보정 탑뷰를 확보하기 전에는 별도 주차 페이지·화면 녹화·새 배점을 제공하지 않는다. 기존 코칭/주차 판별/영상 복기를 유지하고 메뉴는 홈·기록·설정 세 개다.0.13 실험은 빌드에서 제외해 보관했다. 현대/Pleos에서 승인된 탑뷰 영상/스트림/API와 녹화·저장·분석 권한, 차체 외곽·해상도·시각·왜곡/스티칭 보정 정보를 제공하면 재검토한다. 제공 여부는 아직 확인되지 않았다. 다음 GitHub 제출에서도 README에 이 전제와 미구현 범위를 유지한다.
