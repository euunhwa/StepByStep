# EasyCar 0.5.0 · 차량 입력과 임의 평가셋 검증

확인일 2026-11-06 / Asia·Seoul. 실제 프로젝트 `/Users/<user>/AndroidStudioProjects/EasyCar`에서 최종 APK를 빌드하고 Pleos Connect v2.1.0 한 대에 설치했다. CPU2코어·RAM3GB로 제한했고 Gradle과 에뮬레이터를 동시에 실행하지 않았다. 검증 종료 후 코칭은 정지했으며, 앱 홈·에뮬레이터와 localhost:8088 포워딩은 사용자가 계속 조작할 수 있도록 유지했다. 최종 HTTP 응답200을 확인했다.

## 동작 변경

- 기본 **코칭 시작**은 항상 차량 서비스 입력을 사용한다. 예전 demo_input=true가 있어도 합성 입력으로 전환하지 않는 것을 기기 테스트했다.
- 우측 상단 **데모**에서만 제출용 auto-drive를 실행한다. 설정의 합성 기본 입력 전환은 제거했다.
- 홈에서 현재 속도·기어·핸들·진행 방향 품질을 확인할 수 있다. 방향 원시값을 받더라도 품질이 불확실하면 신뢰할 수 있는 진행 방향이라고 표시하지 않는다.
- 사용자 요청에 따라 임의 평가 참조셋7종·926개 예제와12개 비교값을 생성했다. 새 결과는 PROVISIONAL/임시 점수와 기준 공지를 저장한다. 홈·설정·상세·미니 창에 **평가용 데이터셋은 임의로 만든 자료이며 개선이 필요합니다.**를 표시한다.
- 필수 신호·공간·급감속 원인 누락은 계속 보류한다. 기존의 포괄적인 보류 문구 대신 관측값과 실제 보류 이유를 안내한다.
- 주차 영상 분석이 나중에 끝나면 기존 카드의 점수/기준을 갱신하고 음성을 다시 재생하지 않는다.
- 긴 세션 JSON이 SQLite CursorWindow의 한 행 크기를 넘는 오류를 실제 기존 기록에서 발견했다. 원본 기록을 삭제하지 않고64K 문자 단위로 조회하도록 수정했다. 저장 시 전체 과거 기록을 다시 파싱하던 처리도 제거했다.

## localhost 차량 서비스 시험

Virtual Console 브라우저에서 D→ACCEL→BRAKE→P를 조작했다. 앱에 테스트 파형이나 정답 라벨을 넣지 않았고, shell VHAL 주입도 하지 않았다. AAOS PERF_VEHICLE_SPEED, AAOS 기어 및 Pleos 핸들 콜백을 통해 기록했다. **실차 주행 시험은 아니다.**

1. 짧게 가속 후 바로 제동:158프레임, 출발/정지 인식. 급감속 원인이 없어서 양쪽 총점 보류. 문구는 관측 최고 속도와 감속 원인 미확인을 표시했다.
2. 출발 관측4초가 끝난 뒤 제동:269프레임, demoCaseId=null, 모든 속도 출처 AAOS. 출발은 임의 기준에 따른 **임시0점**(콘솔의 최대 가속 조작으로 가속 배점 상한까지 감점), 정지는 급감속 원인 미확인으로 보류했다. 이0점은 실차 안전 능력 판단이 아니다.
3. 두 번째 기록에서 출발 결과 종료→UI 상태 게시4ms, 음성 시작84ms 및 실제 TTS **SPOKEN** 확인. 이는 게시 이벤트 시각이며 화면 픽셀의 렌더 완료 지연을 계측한 수치는 아니다. 정지 결과도3ms 후 게시했고 테스트 종료 당시 음성은 WAITING이었다.
4. 차량 입력에는 parkingScene이 없음을 확인했다. 공간 정보·진행 방향/조향 측정 시각이 검증되지 않은 상태에서 실제 T자/평행/회전 점수가 가능하다고 주장하지 않는다.

## 별도 제출용 데모

우측 상단 버튼을 실제 누르고1배속으로1,112프레임을 재생했다. 출발→좌회전→우회전→유턴→정지→T자→평행을 자동 인식하고 모두 PROVISIONAL로 저장했다. 제출 데모 시험은 무음 설정이므로 이번 시험에서 일곱 음성을 모두 발화했다고 보고하지 않는다. 실제 한국어 발화 완료는 위 차량 서비스 출발 기록에서 확인했다.

| 동작 | 임시 점수 | 근거 |
|---|---:|---|
| 출발/좌회전/우회전/유턴/정지 | 각각100 | 합성 관측값이 임의 비교 범위 내 |
| T자 주차 | 88 | R→D3회, 3×4=12점 감점 |
| 평행주차 | 98 | R→D1회, 1×2=2점 감점 |

주차의 실제 합성 MP4 픽셀 분석 이후 저장 결과와 피드백 카드 점수가 일치한다. 평가 예제와 데모는 같은 합성 계열이므로 이 성공을 독립 데이터셋의 정확도나 모범운전 검증으로 해석하면 안 된다.

## 작은 창과 남은 연동

미니 화면240×180/180×100/840×1000dp에서 콘텐츠 경계를 기기 테스트했다. Pleos2.1.0은 PiP feature가 없으며 시스템 오른쪽 점 세 개 핸들을 왼쪽으로 끌어 내비 옆 분할 창을 사용한다. 실제 분할 화면/배경 음성 증거는 [v0.4 검증](verification-v4-ko.md)에 보존했다. 지원 기기의 PiP 코드는 컴파일했으나 실제 PiP 성공은 미검증이다.

알림 권한은 현재 사용자10에서 미허용이므로 알림 UI 표시를 검증하지 않았다. 현재 사용자10의 CAR_SPEED/FUSED_LOCATION은 기존 사용자 허용 상태로 확인했다. 실제 차종별 신호 시각·진행 방향 품질·카메라/공간 공급원·전문가 평가 자료·Gleo 스키마/권한은 여전히 외부 검증/자료가 필요하다. 실차 카메라 녹화나 Gleo 연동이 완료됐다고 표시하지 않는다.
