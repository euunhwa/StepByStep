# 영상 입력·보정·실제 분석

> 0.13.2 사용자 화면은 각도/px/프레임 수·동기화 설명 대신 쉬운 주차 위치 안내를 표시한다. 보정 파일 연결은 **영상 분석 설정 불러오기**로 표시하며 내부 보정 계약·분석·저장 근거는 유지한다.

앱0.13.1은 사용자 요청으로0.13.0의 별도 주차 페이지·화면 녹화 서비스를 제외하고 기존 영상 가져오기·복기를 유지한다. 상위 메뉴는 홈·기록·설정 세 개다. 실제 위에서 보는 AVM 영상은 미확보이며, 현대/Pleos에서 승인된 탑뷰 영상/스트림/API와 녹화·보정·시각 정보를 제공하면 후속 연동을 재검토한다. [0.13 실험 기록](parking-capture-ko.md)은 현재 앱 기능을 뜻하지 않는다.

앱0.10.0부터 영상 복기는 `parking-vision-2.0`을 사용합니다. [사용법·전체 변경 수치·검증](parking-video-analysis-ko.md)을 참고합니다. 아래 차량 신호 동기화 계약은 유지하며, 영상 근거로 기존 동작 점수를 재계산하지 않습니다.

## 지원 경로

1. **합성 탑뷰 MP4**: 현재 끝까지 동작하는 검증 경로입니다. Swift AVAssetWriter 도구가 480×360 / 15fps / 4초 H.264 MP4 5종(양호·기울어짐·침범·가림·선 없음)을 만듭니다. 기기 카메라나 숙련 운전자 데이터가 아닙니다.
2. **사용자가 선택한 파일**: Android SAF로 선택하고 영상 저장 동의 후 기기 내부 `files/videos`에 복사합니다. 250MB 이하를 받습니다. 보정 정보가 없으면 정렬과 차량 신호 연계를 보류합니다. 복기에서 탑뷰 보정 JSON을 연결하면 실제 픽셀 정렬을 분석하며, 명시적인 시간 매핑이 없으면 차량 신호는 연결하지 않습니다.
3. **실제 내장 어라운드뷰**: 위에서 보는 보정 탑뷰 입력·녹화 경로는 미확보다. 현재 APK에는 화면 녹화 서비스나 EVS 직접 접근이 없다. 현대/Pleos에서 사용·녹화가 허용된 탑뷰 입력과 보정 정보를 제공하면 재검토한다.

## 실제 분석

분석기는 PixelFrame(width, height, argb, timeMs, source)와 Calibration만 받습니다. 파일명·시나리오 ID·정답 각도를 받지 않습니다.

- 국소 대비가 있는 흰색·노란색 픽셀을 수집하고, 제공된 차량 외곽 마스크를 제외합니다. 어두운 흰색과 대비가 충분한 노란색을 지원하며 균일한 밝은 영역을 거부합니다.
- 수직 기준 ±25도에서 0.5도 간격 Hough 투표 후 서로 떨어진 두 선 후보를 찾습니다.
- 검출 픽셀에 최소제곱 회귀를 적용해 투표 bin의 각도 편향을 줄입니다.
- 선의 지지율, 두 선의 평행성, 차량 주변 대상 칸, 선의 개수·가림을 검사합니다. 여러 대상 후보이면 사용자가 대상 칸을 선택해야 한다는 보류 사유를 표시합니다. 보정 정보가 있으면 영상을 멈추고 대상 칸 안쪽을 눌러 실제 검출된 인접 두 선을 선택할 수 있습니다. 선택되지 않거나 검출 범위 밖이면 계속 보류합니다.
- 검출한 두 선의 평균 방향과 제공된 수직 차량축 사이의 각도를 계산합니다. 선 두께의 안쪽 경계와 차량 앞·뒤 모서리의 수직 거리를 계산합니다. ±2px 경계에서는 침범 여부를 보류합니다. 핸들 중앙 여부로 정렬을 판단하지 않습니다.
- metersPerPixel이 있는 입력에서만 좌우 여유와 중앙 편향을 m로 표시합니다. 스케일이 없으면 px만 관측하고 m는 null입니다. 실제 거리·속도를 보정 없는 영상에서 추정하지 않습니다.
- 어두움·선 없음·큰 가림·비평행·보정 미확인이면 angle/intrusion은 null입니다. 보류를 0도 정렬 양호로 바꾸지 않습니다.

## 합성 보정 계약

`SyntheticParkingFrames.calibration`은 탑뷰·왜곡 보정 완료·차량 축 확인이라는 합성 생성 조건을 명시합니다. 기준 영상 480×360, 차량 외곽 x=190~290 / y=95~265, 차량 축 수직, 0.01m/px입니다. 합성 영상이므로 렌즈 왜곡·스티칭 오류는 생성하지 않습니다. 이 보정값을 사용자 영상이나 실차 영상에 적용하지 않습니다.

실차 지원을 추가하려면 카메라별 내부/외부 파라미터, 스티칭 변환, 지면 평면성, 차량 외곽, 축 방향, 위치별 pixel scale 및 오차를 검증해야 합니다. 지원하지 않는 측면·원근 시점은 계속 보류해야 합니다.

## 기존 단일 프레임·신호 동기화와 새 구간 분석

0.10.0 복기에서는 사용자가 선택한 위치 앞 최대1초의5개 요청 시점을 비교해 구간 결과를 별도로 저장합니다. 저장 시각은 영상 시계이며 동작 채점에 사용하지 않습니다. 아래는 기존 단일 프레임 입력과 차량 시각 매핑 계약 설명입니다.

데모는 P + 정차 유지가 확인된 끝 구간에 대응하는 마지막 유효 프레임을 디코딩합니다. MediaMetadataRetriever의 실제 프레임을 분석하고 근거에 프레임 시각을 남깁니다. 종합 점수는 종료 시각보다 미래이거나 1.5초 이상 오래된 프레임이면 보류합니다. 허용된 실차 녹화 입력은 없으므로 종료 직전 실차 프레임 보존은 연결 대기입니다.

합성 생성 시 영상 0~4000ms와 해당 파형의 시작~종료 시각 사이에 선형 매핑을 정의했습니다. 이는 물리적인 촬영 시계 동기화가 아닌 명시적인 데모 시간 매핑입니다. `truth-labels.json`의 sync에 별도로 기록하며 감지 정답에 쓰지 않습니다. 복기에서 이를 표시하고 재생 위치의 속도·기어를 가장 가까운 신호로 보여 줍니다. 사용자 영상에는 이 매핑을 적용하지 않습니다.

복기 재생은 Android VideoView/MediaPlayer, 분석은 MediaMetadataRetriever + 순수 Kotlin 검출기를 사용합니다. 프레임 분석은 background dispatcher에서 실행하며 약 200~300ms 단위로 오버레이를 갱신합니다. 주행 규제 시 복기 화면을 제거하고 stopPlayback을 호출합니다. 영상은 기본 무음 재생입니다.

## 보관·삭제

개인 영상의 가져오기·저장은 별도 동의가 있어야 수행합니다. 번들 합성 입력은 앱 자체 시험 자료입니다. 사용자 파일은 기기 내에 보관하며 자동 외부 업로드 코드는 없습니다. 보관 기간은 7/30/90일이며 앱 시작/설정 변경 시 오래된 기록과 관련 파일을 정리합니다. 기록 삭제 시 해당 사용자 영상 참조·파일을 함께 제거하며 Room 재시작·삭제 일관성을 계측 테스트합니다. 기본 동영상 캐시에는 번들 합성 영상만 복사합니다.


## 사용자 보정 JSON과 대상 칸 선택

복기 화면의 **탑뷰 보정 정보 연결**에서 SAF로 JSON을 선택합니다. `examples/synthetic-top-view-calibration.json`은 번들 합성 영상만을 위한 형식 예제입니다. 실제 영상에 그 좌표를 복사하면 안 됩니다. 사용자가 왜곡/스티칭 보정을 완료한 수직 차량축 탑뷰와 실측 차량 외곽을 제공해야 합니다. 앱이 원근 영상의 카메라 캘리브레이션을 자동 수행하는 기능은 없습니다.

필수: schemaVersion=1, projection=TOP_VIEW_UNDISTORTED, vehicleAxis=VERTICAL, videoWidth/videoHeight, vehicleBounds(left/right/top/bottom). metersPerPixel과 targetCenterX는 선택입니다. 수치 범위, 유한성, 외곽의 영상 내 포함, 시간 구간을 검사합니다. 프레임은 긴 변 최대 640px로 축소하고, 차량 외곽·선택 좌표·m/px를 같은 비율로 변환합니다. 종횡비가 다르면 보정 적용을 보류합니다.

선택 `sync`는 videoStartMs/videoEndMs/signalStartMs/signalEndMs를 갖습니다. 명시한 범위 안에서만 양방향 선형 매핑합니다. 해당 시각의 신호가 없거나 1초 넘게 떨어져 있으면 속도/기어를 표시하지 않습니다. 파일만 가져온 기록에 차량 신호를 만들어 넣지 않으므로 영상만으로 종합 주행 점수를 만들지 않습니다.

여러 선이 검출되면 모두 오버레이하되 확정 정렬은 보류합니다. 정지 화면에서 실제 누른 행의 위치를 포함하는 인접 두 검출선을 선택한 뒤 평행성·지지율·차량 외곽을 다시 계산합니다. 보정/선택 변경 후의 복기 결과가 달라도 당시 제공한 피드백 이력과 음성은 변경·중복 발행하지 않습니다. 0.10.0부터 영상 보정 변경은 구간 영상 근거만 저장하며 원래 동작 점수·근거·피드백·음성을 그대로 보존합니다. 사용자 보정 정보의 실측 정확도 검증과 실제 파일 종류별 기기 호환성 검증은 별도입니다.
