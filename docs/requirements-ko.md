당신은 Android Automotive OS와 Pleos Connect를 다루는 소프트웨어 엔지니어다. 아래 요구사항으로 초보운전자 코칭 앱 ‘차근드라이브’를 구현해라. 이 문서가 구현 지시로 전달된 시점부터 개발을 시작한다. 계획 설명에 그치지 말고, 실행 가능한 앱·분석 로직·검증 자료를 완성해라. 한국어로 소통하고 사용자 화면도 한국어로 작성해라.

<제품_목표>

앱 이름: 차근드라이브

대상: 초보운전자와 장기간 운전을 쉬었다가 다시 시작하는 운전자

차량의 속도·조향각·기어 등으로 좌회전, 우회전, 유턴, 출발, 정지, T자 주차, 평행주차를 분석한다. 동작이 끝난 뒤 안내할 여유가 있는 시점에 짧은 음성을 제공하고, 주행 종료 후 점수·감점 근거·다음 연습 목표를 보여준다. 주차 영상 접근이 허용되면 녹화 영상과 최종 정렬 분석도 제공한다.

<기술_구성>

- 기존 프로젝트와 충돌하지 않으면 Kotlin, Jetpack Compose, ViewModel, Coroutines/Flow를 사용해라. 로컬 기록은 Room, 설정은 DataStore, 영상 재생은 Android에서 지원되는 적절한 플레이어를 사용해라. 실제로 호환되는 버전을 확인하고 고정해라.
- 동작 인식·점수 계산은 Android와 분리된 순수 Kotlin 코드로 작성하고, 테스트 가능한 시간 공급자와 데이터 소스를 사용해라. 모듈 분리는 필요한 만큼만 해라.
- 차량 신호 입력, 영상 입력, 동작 감지, 점수 계산, 코칭 문장, 음성 출력, 로컬 저장을 인터페이스로 분리해라.

- 미지원·권한 없음·연결 끊김·신호 지연을 명시적인 상태로 표현해라. 실차 데이터가 끊기면 자동으로 가짜 데이터로 바꾸지 마라. 데모는 사용자가 명시적으로 선택한다.
- 승인된 차량 상태 읽기와 안내 기능을 구현해라. 조향·가속·제동을 제어하는 기능은 만들지 마라.

<데이터와_모범_기준>

- 속도는 내부적으로 m/s, 운전자 핸들 각도는 degree로 통일하고, 표시할 때 km/h로 변환해라. 전진·후진의 부호 규칙을 정의해라. 핸들 회전각과 실제 앞바퀴 조향각을 혼용하지 마라.
- 각 신호에 측정 시각·수신 시각·단위·출처·품질 상태를 보존해라. 역순·중복·오래된 신호와 큰 데이터 공백을 처리하고, 서로 다른 신호의 시각을 맞춰라.
- 속도에서 가속도와 가속도 변화율을, 조향각에서 조향 변화 속도를 구하되 실제 시간 간격을 사용해라. 잡음 제거 때문에 발생하는 지연을 기록하고, 데이터 공백을 급가감속으로 오인하지 마라.
- ReferenceProfile을 JSON으로 정의해라. 차량 프로필, 동작 유형, 적용 가능한 코스·공간 조건, 동작 단계별 허용 범위, 배점, 버전, 데이터 출처, 검증 상태를 포함하고 불러오기 시 형식을 검증해라.
- 실제 모범 데이터가 없다면 재현 가능한 합성 예제 프로필과 입력 데이터를 제공해라. 이를 ‘데모 기준·합성 데이터’로 표시하고 실제 숙련 운전자의 측정 데이터로 소개하지 마라. 전문가 데이터 수집·가공·검증 방법은 별도로 문서화해라.
- 초기 지원 범위는 제한된 차종·코스·주차 조건으로 명확히 정해라. 도로 폭·회전 반경·주차 공간을 실제로 알 수 없으면 알고 있다고 가정하지 마라. 일반 도로 전체에 보편적으로 적용되는 유턴 적정 속도를 임의로 정하지 마라.
- 비교 조건이나 필수 데이터가 부족하면 해당 항목과 종합점수를 보류해라. 부분 측정값은 표시할 수 있지만 누락된 항목을 0점 감점이나 100점 성적으로 처리하지 마라.

</데이터와_모범_기준>

<상황_인식>

- 주행 세션과 개별 동작을 상태 머신으로 관리해라. 시작·진행·종료·중단·평가 보류 상태와 인식 신뢰도를 보존해라.
- 좌·우회전·유턴은 조향각, 속도, 신뢰할 수 있는 진행 방향 변화, 확보 가능한 위치·내비 정보를 조합해라. 방향지시등이나 순간 조향각 하나만으로 확정하지 마라. 내비가 안내한 동작과 실제 수행한 동작을 구분해라.
- 회전은 진입·회전·탈출로 나누고, 핸들이 복원되며 진행 방향이 안정되는 것을 종료 판단에 사용해라. 곡선 도로, 차로 변경, S자 구간을 회전·유턴으로 오인하는 사례를 포함해라.
- 출발은 정지 상태에서 이동으로 바뀌는 구간, 정지는 감속 후 정지 상태가 유지되는 구간으로 정의해라. 임계값·유지 시간은 설정으로 분리하고 사용한 기본값의 근거와 한계를 기록해라.
- 모델이 알 수 없는 주변 위험 상황 때문에 급제동했을 수 있다. 원인을 확인할 수 없는 급감속은 관측 이벤트로 남기고 운전자 과실로 단정해 자동 감점하지 마라. 통제된 연습·데모에서 원인이 주어진 경우에는 그 맥락으로 평가할 수 있다.
- T자·평행주차 유형은 자동 인식 근거가 없으면 정차 중 연습 모드 선택으로 받거나 ‘주차 유형 미확인’으로 남겨라. 영상 분석 없이 두 유형을 구분했다고 주장하지 마라.
- 데모 입력에 제공한 정답 라벨은 검증에만 사용해라. 자동 감지기가 정답 라벨을 읽어 동작을 맞히게 만들지 마라. 연습 모드에서 사용자가 선택한 유형은 별도 입력 출처로 표시해라.

</상황_인식>

<회전과_출발정지_평가>

- 회전 평가: 진입 속도, 회전 중 속도·가감속, 급격한 조향 변화, 탈출 시 속도·조향 복원의 부드러움을 분석해라. 다른 조건의 모범 데이터와 단순히 절대 핸들 각도를 비교하지 마라.
- 출발 평가: 출발 구간의 과도한 가속과 가속 변화의 급격함을 분석해라.
- 정지 평가: 감속 패턴과 정지 직전 속도 변화를 분석해라. 속도만으로 실제 차체 충격을 직접 측정했다고 표현하지 마라.
- 허용 범위를 벗어난 크기와 지속 시간에 따라 감점을 증가시키고 동작 길이에 따른 불합리한 편향을 줄여라. 짧은 잡음은 제외하고, 한 원인의 중복 감점과 전체 감점에 상한을 둬라.
- 모든 수치와 가중치는 ScoringConfig로 분리해라. 초기값은 ‘시제품용 임시 기준’으로 명시하고, 운전 강사의 평가와 비교해 보정할 수 있게 해라.

</회전과_출발정지_평가>

<주차_평가_필수>

주차는 전후진 반복, 이동 과정, 진입 자세, 최종 정렬을 평가한다. 전후진 횟수에 따른 가중 감점은 확정 요구사항이다.

- 저속 상태의 R단 진입을 주차 시작 후보로 삼아라. 단순 후진과 주차를 혼동하지 않도록 연습 모드 또는 확보한 맥락을 사용해라. 시작 전 진입 구간이 관측되지 않았다면 그 항목을 평가하지 마라.
- 주차 중 D단 전환으로 세션을 끝내지 마라. P단 전환과 정차 상태 유지를 종료 후보로 사용하고, 일시 중단·취소·이탈도 처리해라. P단 신호만으로 반드시 주차가 완성됐다고 확정하지 마라.
- N은 해당 주차 세션에서 안정된 주행기어가 R에서 D로 바뀐 횟수다. D→R은 추가로 세지 않는다. R→중립기어→D는 R→D 1회로 센다. 같은 기어의 반복 콜백이나 순간 신호 흔들림은 중복으로 세지 마라. 중립기어 N과 횟수 변수 이름을 코드에서 구별해라.
- 데모용 횟수 감점 기본값은 min(30, N × (N + 1))점으로 둬라. 0회=0점, 1회=2점, 2회=6점, 3회=12점, 4회=20점, 5회 이상=30점 감점이다. 이는 사용자가 확정한 배점이 아닌 제안된 임시값이므로 설정으로 교체할 수 있어야 한다. 첫 전환부터 감점하고, 임의로 무료 허용 횟수를 추가하거나 이 항목을 제거하지 마라.
- 주차 과정은 전·후진 이동 속도, 급가속·급감속, 조작의 부드러움을 분석해라. 이동 속도는 차량 신호를 사용하고, 보정되지 않은 영상만으로 절대 속도를 정확히 측정했다고 주장하지 마라.
- 진입 자세는 주차 유형과 공간 조건에 맞는 허용 범위로 비교해라. 초기에 하나의 고정 진입각을 모든 주차에 적용하지 마라.
- 최종 정렬은 차량 기준축과 대상 주차칸 방향의 상대 각도, 주차선 침범 여부, 관측 가능한 좌우 여유 공간을 분석해라. 핸들이 중앙이라는 이유로 차가 주차선과 나란하다고 판단하지 마라.
- 주차 점수는 100에서 횟수 가중 감점, 이동·조작 감점, 진입·최종 정렬 감점을 빼서 0~100으로 제한해라. 횟수 항목은 삭제하지 않되, 다른 필수 항목이 누락되면 최종 종합점수는 보류하고 확정된 횟수 감점을 별도로 보여줘라.

</주차_평가_필수>

<주차_영상>

- 영상 소스는 승인된 어라운드뷰 입력, 사용자가 제공한 영상 파일, 명확하게 표시한 합성 데모 영상으로 분리해라. 공식 접근 경로와 녹화 허용이 확인되지 않은 내장 카메라는 ‘연동 미확인’으로 표시해라. 화면에 어라운드뷰가 나온다는 이유로 캡처·녹화 가능하다고 가정하지 마라.
- 녹화·저장은 사용자가 동의한 경우에만 수행하고 기본은 기기 내 처리·보관으로 해라. 보관 기간 설정과 기록·영상 삭제 기능을 제공하고 외부 서버로 자동 업로드하지 마라.
- P단 전환으로 카메라가 꺼지는 경우에 대비해, 허용된 입력에서 종료 직전의 마지막 유효 정차 프레임을 보존해라. 너무 오래된 프레임을 최종 결과로 쓰지 마라. 저장 가능한 입력이 없으면 녹화 성공 상태를 만들지 마라.
- 차량 기준축과 영상 좌표 관계를 알 수 있는 탑뷰 입력부터 지원해라. 왜곡·스티칭·카메라 보정·차량 외곽 기준을 정의하고, 지원하지 않는 카메라 시점은 분석 보류해라.
- 제공된 영상 또는 합성 시험 프레임에서 주차선을 실제로 검출하는 분석 경로를 구현해라. 이미지에서 찾은 선과 차량 기준으로 정렬 각도를 계산하고 결과를 영상 위에 표시해라. 영상 파일명이나 시나리오 ID로 정렬 각도를 반환하는 가짜 분석을 만들지 마라.
- 대상 주차칸이 여러 개면 확신할 수 있는 경우에만 선택하고, 필요하면 주차 후 사용자가 선택하게 해라. 선 가림·저조도·보정 정보 부족 시 인식 품질을 낮추거나 평가를 보류해라. 미터 단위 여유 공간은 보정 정보가 있을 때만 표시해라.
- 영상과 차량 신호의 시간을 맞춰 재생 위치에 해당하는 속도·기어·평가 근거를 보여줘라. 동기화 정보가 없으면 임의로 연결하지 마라.
- 실차 카메라가 없어도 승인된 파일 또는 합성 영상으로 ‘영상 입력→실제 분석→재생·오버레이’가 동작하는 경로를 완성해라. 합성 영상의 생성·분석은 데모라는 사실이 화면과 문서에 드러나야 한다.

</주차_영상>

<점수_근거와_코칭>

- 동작마다 종류, 구간, 점수 또는 보류 사유, 항목별 감점, 측정값, 적용 기준, 기준 버전, 근거 시각, 인식 품질, 데이터 출처를 저장해라. 소수점 반올림과 상한 적용 후에도 화면의 감점 합계와 최종점수가 일치해야 한다.
- 예: ‘유턴 80점 / 진입 속도 높음 −12 / 급격한 조향 변화 −8’. 이는 표시 형식 예시다. 실제 점수는 입력 신호에서 계산하고 예시 숫자를 결과에 하드코딩하지 마라.
- 예: ‘주차 78점 / 전후진 반복 −12 / 주차 속도 높음 −6 / 최종 정렬 기울어짐 −4’. 이 예시는 위 임시 횟수 기준에서 R→D 3회에 해당한다. 다른 항목의 배점 역시 설정과 측정 근거가 있어야 한다.
- 음성은 확인된 개선점 하나를 짧게 말해라. 예: ‘이번 유턴은 진입 속도가 높았어요. 다음에는 회전을 시작하기 전에 충분히 감속해 보세요.’ 관측하지 않은 도로 상황이나 운전자 행동을 지어내지 마라.
- 주행 후에는 잘한 점 하나, 개선할 점 하나, 다음 연습 목표 하나를 제공해라. 근거가 없으면 억지로 칭찬·지적을 만들지 마라.
- 점수는 결정적인 계산 엔진이 정하고 AI는 그 결과를 설명한다. 외부 LLM 없이도 검증 가능한 한국어 템플릿으로 동작하게 해라. LLM을 추가하는 경우에도 점수·관측값·원인을 임의로 바꾸지 못하게 하고 실패 시 템플릿으로 돌아가라.
- 자동 코칭 음성은 확인된 Pleos TTS를 사용하고, 데모에서는 일반 Android TTS 등 사용 가능한 대체 출력을 사용해라. 자동 음성 전체를 글레오 AI가 제공한다고 표시하지 마라.
- 글레오 연동이 확인되면 ‘방금 유턴은 어땠어?’, ‘왜 감점됐어?’, ‘오늘 개선할 점 알려줘’라는 요청에 기존 평가 기록을 반환하는 기능을 연결해라. 스키마·등록·권한이 확보되지 않았다면 연동 미확인 상태와 연결 명세를 제공해라. 임의의 글레오 API 호출이나 실제 AI 대화처럼 꾸민 고정 응답은 금지한다.

</점수_근거와_코칭>

<사용자_경험과_지속_실행>

- 화면은 시작·동의, 홈, 주행 중 최소 화면, 주행 후 요약, 동작 상세, 주차 영상 복기, 성장 기록, 설정으로 구성해라. 빈 기록·권한 거부·미지원·데이터 부족·오류 상태도 구현해라.
- 차량 환경에 맞는 큰 터치 영역, 높은 대비, 간결한 한국어와 가로 화면을 우선해라. 색상만으로 평가 상태를 구분하지 마라. 주행 중 상세 그래프·긴 감점 목록·영상·설정 조작은 제한해라.
- 실차에서는 CarUxRestrictions와 플랫폼 오디오 정책을 따르고, P단 여부만으로 영상 재생 허용을 결정하지 마라. 주행 제한 상태를 모르면 제한된 화면으로 동작해라.
- 동작 종료 시 결과를 저장하고 음성은 조건이 허용될 때 제공해라. 회전·후진 중, 내비 안내·안전 경고·통화 등 우선 오디오와 겹칠 때는 보류해라. 확인할 수 없는 오디오 상태를 확인했다고 가정하지 마라.
- 음성 빈도 제한, 중복 억제, 오래된 안내 폐기, 무음 설정을 구현해라. 안정된 직진 등 관측 가능한 안내 조건을 사용하되, 센서만으로 주변이 안전하다고 보장하는 문구는 쓰지 마라. 허용 시점이 없으면 주행 후 요약으로 넘겨라.
- 내비 앱이 전면에 있어도 분석을 지속하는 실행 경로를 지원 조건에 맞춰 검토해라. 허용되는 서비스 수명주기와 권한을 사용하고, 화면 전환·앱 재생성·연결 해제·재연결 때 중복 구독과 기록 손실을 처리해라. 자동 시작과 상시 실행 가능 여부는 별도로 검증해라.
- 핵심 분석·점수·기록·기본 코칭은 오프라인에서도 동작하게 해라. 제한을 우회해 경고·오버레이·백그라운드 기능을 강제하지 마라.
- 홈과 보고서에 실제 입력 출처와 모범 기준의 검증 상태를 명확히 표시해라. 개발용 내부 용어는 일반 사용자 흐름에 과도하게 노출하지 마라.
- 성장 기록은 같은 유형·유사 조건·같은 평가 버전끼리 비교해라. 데이터가 부족하면 개선 추세를 단정하지 마라. 개인의 과거 점수에 맞춰 모범 기준을 자동으로 낮추지 마라.

</사용자_경험과_지속_실행>

<데모와_검증>

다음 사례를 같은 입력·인식·채점 경로로 재생할 수 있게 해라. 입력 파형, 영상, 정답 라벨, 기준 프로필을 구분해 제공하고 반복 실행 결과를 재현할 수 있게 해라.

- 정상 좌회전·우회전·유턴과, 조건이 동일한 과속 진입·급격한 조향 사례.
- 부드러운 출발·정지와 급출발·거친 정지, 원인을 알 수 없어 평가를 보류하는 급감속 사례.
- 곡선 도로·차로 변경, 진행 방향 신뢰도 부족으로 동작을 확정하지 않는 사례.
- T자·평행주차의 R→D 전환 횟수 0~5회 사례와 반복 콜백·중립기어 경유 사례.
- 정렬이 양호한 주차, 기울어진 주차, 주차선 침범, 선 가림 또는 영상 부재로 일부 평가를 보류하는 사례.
- 신호 지연·누락·역순·연결 끊김·주행 규제 변화·오디오 중단 사례.

의미 있는 자동 검증을 작성해라. 화면 문구나 함수를 그대로 복제하는 테스트보다 아래 동작을 검증해라.

- R→D 가중 감점이 0, 2, 6, 12, 20, 30점으로 적용되고, 중복 신호는 횟수를 늘리지 않는다.
- 같은 조건에서 허용 범위 이탈이 커지거나 길어지면 감점이 감소하지 않는다. 신호 잡음·공백 때문에 가짜 급출발·급정지가 생기지 않는다.
- 신뢰도가 낮은 회전은 확정되지 않고, 필수 입력 누락은 100점으로 처리되지 않는다.
- 최종점수는 0~100이며 표시된 감점 합계와 일치한다. 재생 속도를 바꿔도 분석 결과는 변하지 않는다.
- 알려진 각도의 시험 영상에서 정렬 각도가 허용 오차 안에 들어오고, 선이 없는 영상은 평가 보류된다. 측정값을 상수로 반환해 통과시키지 마라.
- 주행 제한 중 영상 재생·상세 화면이 제한되고, 음성은 중복되거나 우선 오디오를 방해하지 않는다.
- 저장·재시작·삭제 후 기록과 영상 참조가 일관된다.

프로젝트에 적절한 빌드·분석·테스트를 실제 실행하고 실패 원인을 해결해라. 에뮬레이터가 있으면 주요 흐름을 실행해 화면을 확인해라. 환경에 없는 SDK·기기 때문에 못 한 검증은 실행하지 못했다고 기록해라. 테스트 통과를 운전 평가 정확도나 실차 사용 승인으로 해석하지 마라.

</데모와_검증>

<결과물과_완료_조건>

결과물은 소스 코드, 재현 가능한 빌드 설정·래퍼, 데모 입력·영상·기준 프로필, 실행 가능한 데모 앱, 의미 있는 테스트, 한국어 실행 안내다. 빌드가 성공한 경우 생성된 APK 경로를 제공하고, 생성하지 못한 APK가 있다고 보고하지 마라.

README에는 실행 절차, 데모 시연 순서, 실제 지원한 기능, 실차 연동 조건을 적어라. 별도 문서에는 API 근거·권한·확인 버전, 신호/프로필 데이터 형식, 채점 수식·임시 기준, 영상 보정 조건, 전문가 기준 검증 계획을 기록해라. 기능별로 ‘구현·테스트됨 / 실제 기기 검증 필요 / 외부 권한·자료 대기 / 미지원’을 구별해라.

완료 판단은 다음과 같다.

- 일반 Android 에뮬레이터의 데모에서 동작 감지→근거 있는 채점→음성 안내→로컬 저장→복기까지 이어진다.
- 주차 R→D 횟수 가중 감점이 실제 계산되고 테스트된다.
- 승인된 영상 파일 또는 합성 영상에서 실제 주차선 분석과 복기 화면이 동작한다.
- 미확보 데이터·권한은 정직하게 보류·미지원 상태로 표시되며 숨겨진 가짜 결과가 없다.
- 실행한 검사와 수행하지 못한 검사를 구분하고, 실차·카메라·글레오 연동의 남은 조건을 보고한다.

검증 가능한 부분을 모두 완성한 뒤 최종 답변에 앱 실행 방법, 생성된 파일·APK 위치, 검증 결과, 미확보 연동 조건을 간결하게 보고해라. 외부 조건 때문에 전체 실차 기획을 완성할 수 없다면 데모 완료와 전체 기획 완료를 혼동하지 마라.

</결과물과_완료_조건>
