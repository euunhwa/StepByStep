# 8088 콘솔 입력으로 촬영 · 0.9.3

2026-11-07. 사용자가 8088 연동 보완과 에뮬레이터 표시를 승인했고, 앱 음성을 포함한 창 녹화 권한을 직접 허용했다.

## 입력과 점수의 출처

호스트 촬영 스크립트는 브라우저가 사용하는 `127.0.0.1:8088/vehicle/gear`, `/vehicle/controls`로 기어·속도·핸들을 입력한다. 정상 `/browser/session` heartbeat를 유지해 DDS가 활성화되게 한다. 앱은 일반 코칭 시작 경로에서 차량 서비스를 관측한다. 내장 데모를 선택하거나 동작명·점수를 앱에 주입하지 않는다.

서버는 정수 km/h·정수 조향각만 허용한다. DEBUG 에뮬레이터에서만 `yaw = signedSpeed / 2.7 × tan(steering / 15)` 모델을 사용한다.2.7m·조향비15는 시연 가정이며 차량 보정값이 아니다. 모델의 출처는 `EMULATOR_BICYCLE_MODEL_NOT_SENSOR`, 시각은 시뮬레이션 계산 시각이다. 화면과 기록에 에뮬레이터/모델 사용을 표시한다. 실차와 release 빌드에는 모델을 사용하지 않는다.

실제 콘솔과 SDK 핸들의 부호가 반대인 것을 장치에서 확인해 호스트가 `-steeringDeg`를 전송한다. 수신된 SDK 핸들을 모델이 그대로 사용하며, 동작 분류는 실제 결과로 확인한다. 에뮬레이터의 기어·핸들 현재 상태 읽기는200ms, 실차는 기존500ms다.750ms 신선도 제한과 평가 기준은 그대로다.

| 출발 | 파랑100 | 정차10초 확인 후 완만한 출발 |

주차 교정 중 짧은1km/h 이동으로15초 장기 정차 종료를 피하며, 각 기어를2초 유지해500ms 안정 조건을 충족한다. 평가식·프로필·과거 기록을 바꾸지 않았다. 인식 경계의4초 정차 창이 지터 때문에 성립하지 않던 문제는 경계 직전 표본을 보존하도록 수정했다. 수치 문턱을 바꾸지 않았다.

## 촬영 방법

- 촬영 보조 계측 검사는 일반 `ActivityScenario`의 실제 화면 시계를 사용한다. Compose 테스트 규칙의 가상 시계를 사용하면 상태 계산과 별개로 영상 화면이 갱신되지 않을 수 있어 사용하지 않는다.
- `state.motion`과 실제 `record.frames` 유입을 확인한 뒤 촬영/주행을 시작한다. 장면마다 새 세션을 사용한다. 음성 완료까지 정차/직진을 유지한다.
- ScreenCaptureKit으로 에뮬레이터 창과 해당 프로세스의 오디오만 H.264/AAC MP4로 녹화한다. 마이크와 다른 앱 화면은 포함하지 않는다.
- 원본 MP4·제어 요청·실제 수신 프레임·결과·음성 상태를 보존한다. 최종 영상에는 장면 구분, 창 테두리 제거, 음량 보정을 적용한다. 실제 점수나 인식 문구를 영상에 덧씌우지 않는다.

호스트 실행기는 [record_console_showcase.py](../tools/record_console_showcase.py), 장치 관찰기는 [ConsoleShowcaseCaptureTest](../app/src/androidTest/java/com/example/easycar/ConsoleShowcaseCaptureTest.kt)다.
