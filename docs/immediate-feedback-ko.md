# 동작 종료 직후 화면·음성 피드백

v0.2.0의 우선순위는 **지정한 상황이 지나면 주행을 계속하는 동안 바로 피드백을 받는 것**입니다. 사용자 요청에 따라 앱 이름은 EasyCar를 유지하고, 주차 R→D 가중 감점도 유지했습니다.

## 실행 경로

`차량/데모 입력 → TelemetryPipeline → CoachEngine.accept → 완료 이벤트 → 화면 카드 + Room 체크포인트 → 발화 조건 확인 → TTS → 실제 시작/완료 상태 저장`

- 좌/우회전·유턴: 핸들 복원과 진행 방향 안정이 확인되면 이벤트를 발행합니다. 진행 방향이 불충분하면 종류 미확정과 점수 보류를 발행합니다.
- 출발: 정지 후 이동 구간을 관측하고 출발 창이 끝나거나 감속으로 전환되면 발행합니다.
- 정지: 감속 후 정차가 유지되면 발행합니다.
- T자/평행주차: 정차 중 선택한 연습 맥락에서 저속 R부터 관측하고 P + 정차 유지 후 발행합니다. 영상 근거가 없으면 횟수 감점은 유지하고 종합점수는 보류합니다. 세션 전체 종료를 기다리지 않습니다.

선택 연습에서는 해당 유형의 피드백을 바로 제공합니다. 예를 들어 좌회전 전 출발 이벤트가 먼저 감지돼도 그 음성이 좌회전 안내를 밀어내지 않습니다. 전체 주행에서는 모든 완료 동작을 순서대로 제공합니다. 파형·정답 파일의 라벨로 회전을 맞히지 않습니다.

## 화면과 음성은 독립

`ImmediateFeedback.publish()`가 화면 카드와 피드백 이력을 동기적으로 만듭니다. 무음·TTS 미설치·초기화·포커스 거부·우선 오디오·음성 간격 때문에 카드가 사라지지 않습니다. 카드에는 완료 유형, 계산 점수 또는 보류, 짧은 조언, 발화 상태와 대기 이유가 있습니다.

음성은 정차 또는 관측 가능한 안정된 직진, 회전/후진 아님, 공개 Android 재생 상태 확인, 통화 아님, 실제 오디오 포커스 승인, TTS 준비를 확인합니다. 실제 주변 위험까지 판단한 것으로 표현하지 않습니다. 포커스 상실과 다른 오디오 시작 시 중단합니다. Android 밖의 OEM 경고·실제 내비/통화 통합 동작은 별도 검증이 필요합니다.

기본 간격 6초(설정 3/6/15/30초), 유효 기간 18초, 최대 대기 4개, resultId 중복 억제를 적용합니다. 종료나 만료로 전달하지 못한 안내도 요약에 보존합니다. 마지막 동작의 음성이 진행 중이면 최소 화면에서 최대 20초 기다리며, 사용자는 주행 종료로 바로 요약으로 이동할 수 있습니다.

## 저장과 계측

동작 완료 직후 결과를 먼저 저장하고 발화 콜백은 같은 결과의 상태를 갱신합니다. 단조 증가 revision으로 늦은 콜백의 오래된 저장이 최신 프레임/결과를 덮지 않도록 합니다. 영상 재분석은 결과를 갱신하되 당시 발행한 피드백이나 음성을 새로 만들지 않습니다.

`FeedbackReceipt`는 resultId·유형·문장·점수·원래 동작 종료 시각·발행 시각·발화 상태/이유를 보존합니다. `visualDelayMs`는 감지 콜백 이후 카드 **데이터 발행**까지의 시간이며 화면 패널의 실제 광학 지연 측정은 아닙니다. `deliveredDelayMs`는 실제 TTS onStart까지의 시간으로 갱신합니다. 단순 요청 수락을 음성 완료로 간주하지 않습니다.

`ImmediateCoachFlowTest`는 일곱 유형 각각에 대해 세션 ACTIVE 상태에서 카드가 존재하고 원래 파형 끝 전에 이벤트가 생성되는지 검사합니다. 조언 문장 전체가 주행 화면 영역 안에 들어오는지, 실제 TTS 시작·완료, 발행 1초 이내·발화 시작 2.5초 이내를 검사하고 JSON/스크린샷을 남깁니다. 무음 카드와 마지막 음성 대기 중 종료도 검사합니다. 수치는 에뮬레이터 시험 조건이며 실차의 보장된 응답 시간이나 스피커 청취 결과가 아닙니다.
